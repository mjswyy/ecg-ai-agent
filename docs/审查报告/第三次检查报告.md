## 3. 红线级发现清单（8 🔴，全部含文件:行号与独立证据）

### 🔴-1 分类器失败被包装成"未检测到高置信度异常→常规随访"（医疗安全反模式残留）
- **位置**：`src/agent/core/agent.py:426-460, 199, 379-384`
- **问题**：诊断分类器失败/空结果时，输出 `diagnosis=[]、incomplete=False、recommendations=['未检测到高置信度异常。建议常规随访。']`。失败被静默呈现为"正常"结论。失败判定仅在"全部步骤失败"时触发，漏掉"测量步骤成功但诊断分类失败"这一最常见模式。
- **证据（端到端复现）**：mock LLM + ToolRegistry，classify_arrhythmia 返回 `{"error":"未加载分类模型"}`、extract_r_peaks 正常 → 输出 diagnosis=[]、confidence=0.0、heart_rate=72.0、rhythm='normal rate (regular)'、incomplete=False、recommendations=['未检测到高置信度异常。建议常规随访。']。根因：`_execute_step` 异常路径也置 completed=True（:319），`incomplete` 恒 False；`_synthesize_diagnosis` 中 classify 的 error 仅计入 n_failed_steps，因 n_ok_steps=1 使 analysis_failed=False。
- **处置**：⚠️ 修复中断（仅 `classification_failed` 计数已加入，recommendations 分支尚未接入）。

### 🔴-2 预处理划分仍按记录而非患者（processed 目录）
- **位置**：`scripts/preprocess_data.py:145-162`
- **问题**：train/val/test 按记录粒度 70/15/15 切分，同一患者多次心电跨划分。processed 划分仍是 preprocess_data_5k 的"事实来源"之一。
- **证据**：ptb-xl 实测 2075 名患者有 >1 条记录，其中 1073 名患者记录横跨 train/val/test。
- **处置**：⏳ 未修（processed 目录为历史记录级产物；5k 已患者级）。

### 🔴-3 processed 与 processed_5k 两套划分并存、互相矛盾
- **位置**：`scripts/preprocess_data_5k.py:16,214-225,342`
- **问题**：磁盘 processed = 30167/6462/6472（记录级 70/15/15），processed_5k = 30232/3763/3754（患者级 80/10/10）。15,411/37,749（40.8%）条记录在两个数据集处于不同划分；其中 4,492 条 processed-test 进入 5k-train、2,605 条 processed-train 进入 5k-test。跨数据集混用即泄漏。
- **证据**：两个目录 manifest 逐条交叉核对。
- **处置**：⏳ 未修（建议统一划分来源并在文档声明 processed 为历史产物）。

### 🔴-4 preprocess_data_5k.py 重跑会复制旧错误标签
- **位置**：`scripts/preprocess_data_5k.py:341`（`m["labels"] = old["labels"]`）
- **问题**：直接复制旧 processed manifest 的 labels（旧版码-名错配 LabelExtractor 产物）。重跑该脚本会把当前已修正的官方 27 类标签覆盖回错误标签。
- **证据**：processed manifest 42,618/43,101 条 labels 与官方映射不符（例：dx_codes=["164889003"]=AF 的记录旧 labels 在 index 5 置 1=Q Wave Abnormal，正确应为 index 2=AF）；processed_5k 磁盘上 37,749 条 labels 与官方映射 0 条不符（已修正）。
- **处置**：⏳ 未修（labels 应在线用当前 LabelExtractor 编码）。

### 🔴-5 知识库相关性过滤的"rhythm"子串误放行——Pacing Rhythm 类被无关诊断污染
- **位置**：`scripts/compile_knowledge.py:92-95,105-107,109-129`（`_text_matches` 裸子串 `any(w in tl)`）
- **问题**：类关键词把 'pacing rhythm' 拆为 ['pacing','rhythm']，'rhythm' 是 'arrhythmia'/'arrhythmogenic' 的子串，几乎任何心律失常摘要都通过相关性把关。
- **证据（实测）**：`classes.json` 的 'Pacing Rhythm' 类 ecg_criteria 含 'Brugada type 1 ECG pattern…BrS diagnosis'、'Prolonged QT interval for LQTS'、'LV depolarization/repolarization…ACM'、'Interatrial block (IAB)' 等，来源 pubmed_32893267（LQTS/BrS）、pubmed_37844667（ACM）、pubmed_39168297（IAB）——与起搏节律完全无关，仅因含 'rhythm' 子串通过过滤。这些错误特征正以"Pacing Rhythm 的诊断特征"注入 LLM。
- **处置**：⏳ 未修（建议词边界匹配 + 剔除通用词 + 强制 PubMed 条目 condition 相似度）。

### 🔴-6 报告重建脚本丢弃 split 字段，废掉 CLIP 防泄漏双保险
- **位置**：`scripts/rebuild_ptbxl_reports.py:27-28`
- **问题**：重建 ptbxl_reports.json 时只写 report 字段、遍历整份 CSV（15110→21799 条），丢掉了原备份中每条记录自带的 split 字段。
- **证据**：当前 ptbxl_reports.json = 21799 条、每条仅 report 字段；备份 .mojibake_bak = 15110 条含 ['split','ecg_id','report','scp_codes','dx_codes']。`extract_text_embeddings.py:74` 依赖 `reports[r].get('split','unknown')`，重建后恒为 'unknown'；`train_ecg_text_clip.py:111` 的 split 一致性红线检查随之失效。
- **处置**：⏳ 未修（重建时应回填 split 并只输出实际使用的 15110 条）。

### 🔴-7 论文三臂 rubric 的 main/report 分数（3.22/3.25 及三维分解）无法在磁盘复现
- **位置**：`paper/main.md:111,115` vs `outputs/agent_eval/judge_rubric_results.json`
- **问题**：当前 judge_rubric_results.json **仅含 kb_arm**（kb 臂单独重打分时覆盖了三臂文件）；论文宣称的 main=3.22（2.91/2.80/4.15）、report=3.25（2.89/2.85/4.17）在任何磁盘产物中均不存在。grep 全 outputs 找不到 3.22/2.91/4.15/2.89/2.85/4.17；历史产物 judge_rubric_results_all.json（main=2.962/report=3.038）与 prelitfl（main=3.12/report=3.241）均为过期的 133 条旧集分数。

### 🔴-8 论文"决策层情境敏感性 100%"与磁盘实测 97.5% 矛盾
