## 2. 方向诊断：为什么之前的路线"不太合理"

### 2.1 问题一：多模态 0.971 是标签泄漏 🔴

`train_multimodal.py` 在**推理时**把医生的报告文本（`reports[rid]["report"]`）输入模型，去预测由该报告定义的诊断标签。报告里写着"sinus rhythm, LBBB"，标签就是这两项——模型在抄答案。0.971 不可用于论文，审稿人一眼看穿。

**修复方向（对应决策 C）**：
- **路线 A（公平版）**：文本只在**对比预训练**阶段使用（ECG-Text CLIP 对齐嵌入空间），下游分类器**推理时只吃信号**，报告 AUC 与 0.897/0.850 公平可比。
- **路线 B（诚实版）**：Agent 拥有 `read_report` 工具。评估分两组：`Agent(信号)` vs `Agent(信号+报告)`，并明示"报告辅助"场景。此时 0.971 级别的数字合法，但必须配无报告组的对比（预计信号-only ≈ 0.90 左右）。

### 2.2 问题二：Agent 目前没有增量价值 🟠

`eval_agent.py` 里的工具调用是**硬编码顺序**（R峰→HRV→QT→分类），不是 LLM 自主规划；Top-5 94% 只是分类器精度。论文需要回答："Agent 比直接调模型多了什么？"

**必须补齐的 Agent 专属评测**（§4 里程碑 M2）：
- 工具选择正确率（LLM 生成的计划 vs 黄金计划）
- 自反思纠错率（注入错误工具输出，看反射器能否纠正）
- 幻觉率（LLM 结论 vs 工具实际输出的不一致比例）
- 情境敏感性（同一波形 × 不同患者情境 → 输出变化是否符合临床预期）
- 有无报告工具的对照

### 2.3 问题三：自训模型碰到天花板（正常，需换叙事）🟡

从零训练的集成 0.850 < ECGFounder 冻结特征 0.897。继续压榨自训模型边际收益低。**正确叙事**：自训系列（0.59→0.79→0.81→0.84→0.85）作为论文里"预训练价值的实证曲线"，ECGFounder 作为主编码器。自训经验（BCE+正则、lr=5e-5、NPU 适配）整理为方法学附录/教学材料。

### 2.4 问题四：ECGFounder 预处理不兼容 🟠

官方 `dataset.py` 要求：**5000 样本（10s@500Hz）**、导联顺序 `I,II,III,aVR,aVL,aVF,V1-V6`、`filter_bandpass` 官方滤波、全信号 z-score。
你们当前管道是 **4096 居中裁剪**（把 10 秒信号砍掉 904 个样本）+ 自己的 0.5-45Hz + 50Hz 陷波 + 逐导联 z-score。线性探针仍得 0.897 说明模型鲁棒，但正式使用必须走官方协议——**且 4096 的 npy 已丢失信息，必须从原始 WFDB 重做 5000 样本版**（原始数据在 `桌面\ECG`）。

## 4. 各里程碑详细任务

### M0：数据与基准重构（1 周）

**M0.1 ECGFounder 兼容预处理管道**（1-2 天）
- 位置：`ecg-ai-agent/src/data_pipeline/` 新增 `preprocessor_5k.py` 或在现有 `ECGPreprocessor` 加 `target_length=5000` 配置
- 规格：500Hz → 5000 样本；导联顺序 `I,II,III,aVR,aVL,aVF,V1-V6`；官方 `filter_bandpass`（从 `GitHub上的一些项目\ECGFounder\util.py` 复制）；全信号 z-score；不做 50Hz 陷波（与官方一致）
- 输入：`桌面\ECG\classification-of-12-lead-ecgs-the-physionetcomputing-in-cardiology-challenge-2020-1.0.2` 原始 WFDB
- 输出：`data/physionet2020/processed_5k/` 新目录（与旧 4096 目录并存，互不污染），复用现有 70/15/15 划分和 `splits` 清单
- 验收：`processed_5k` 下 npy 形状全部 (12,5000)；与原 4096 版标签 100% 一致；抽 5 条与官方 `ptbxl_eval.py` 流程对拍

**M0.2 ECGFounder 冻结特征 + MLP 头**（1-2 天）
- 新建 `scripts/train_ecgfounder_head.py`：ECGFounder 冻结 → 提取 1024 维特征（存 npy，避免重复推理）→ 2 层 MLP（512→27，dropout 0.3）训练
- 同时保留逐类 LogisticRegression 线性探针作为下界
- 预期：MLP ≥ 0.897；目标 ≥ 0.90
- 验收：Bootstrap CI（1000 次）+ 逐类 Youden 阈值 + 与集成 0.850 的 McNemar 检验

**M0.3 MIMIC-IV-ECG 落地**（下载完成后 0.5 天）
- `tools\extract_and_verify.ps1` 解压到 D:\ecg（或指定盘）+ `sha256sum -c` 校验
- 盘点：`record_list.csv`（~80 万行）、`machine_measurements.csv`（工具 grounding 金标准候选）、波形 `files/pXXXX/`
- 近期只做**小规模抽取**（如 2,000 条分层样本），全量训练以后再说

**M0.4 评估协议固化**（0.5 天）
- `src/evaluation/metrics/` 落地：macro AUC + Bootstrap 95% CI、逐类 Youden 阈值、macro F1@Youden、mAP、Top-K、McNemar
- 以后所有模型对比**统一走这个协议**，避免指标口径漂移

### M1：公平的多模态（2 周）

**M1.1 预计算文本嵌入**（1 天）
- PubMedBERT（`microsoft/BiomedNLP-BiomedBERT-base-uncased-abstract-fulltext`）对 15,110 条报告编码，mean pooling → (15110, 768) 存 npy
- 本地 CPU 约 1-2 小时；以后 CLIP 训练不加载 BERT，只读 npy（训练快 10 倍）

**M1.2 ECG-Text CLIP 预训练**（3-4 天含调参）
- 新脚本 `scripts/train_ecg_text_clip.py`：ECGFounder 特征(1024) → Projector(512)；文本 npy(768) → Projector(512)；InfoNCE, τ=0.07, batch 256
- 用 15,110 对数据，NPU 上 ~1h/epoch 量级；评估：检索 recall@1/5（信号→文本、文本→信号）作为对齐质量指标
- 修复 Phase 3 已知 3 个 bug（`SimpleECGProjector.feature_dim`、`LateFusion` 零张量维度、`ECGTokenizer` 下游接入）

**M1.3 公平下游评测**（2 天）
- 架构：ECGFounder 冻结特征 + （可选）CLIP 投影特征 + 元数据编码器 → CrossAttention/Gated/Late 三种融合 → 27 类头
- **推理时只有信号和元数据，绝无报告文本**
- 对照矩阵：
  | 变体 | 输入 | 预期 |
  |------|------|------|
  | ECGFounder-MLP（M0.2） | 信号 | ≥0.90 |
  | + CLIP 预训练投影 | 信号 | +0.005~0.02？ |
  | + 元数据融合 | 信号+年龄性别来源 | 观察增益 |
- 若 CLIP 增益小，如实写进论文（负结果也有价值：说明在 15K 规模下文本监督有限，为 MIMIC-IV-ECG 规模化留下动机）

**M1.4 泄漏红线检查**（每次评测前执行）
- 确认测试集报告文本从未进入训练/验证/推理路径
- 确认按 `patient_id` 划分（PTB-XL 同一患者多记录）

### M2：Agent 实战化与真实评估（2-3 周）

**M2.1 真实 LLM 接入验证**（2 天）
- `LLMInterface(backend="deepseek", model="deepseek-v4-pro")` 真机联调：Planner 输出计划 JSON、Reasoner 输出 CoT、Reflector 输出 pass/replan
- 若 DeepSeek API 不可用：备选 `Qwen/Qwen2.5-14B` 部署到华为云（或按当时最新可用方案）；论文需注明 LLM 版本
- 输出格式约束：JSON schema + 重试解析 + 失败 fallback（现有 `llm_interface.py` 已有骨架）

**M2.2 工具升级**（2 天）
- `classify_arrhythmia` → ECGFounder-MLP（替换旧集成）
- 新增 `read_report` 工具（仅"报告辅助"分支启用）
- 保留 `extract_r_peaks`/`compute_hrv`/`measure_qt_interval`/`plot_waveform`
- （可选）HeartPy 替换 Pan-Tompkins，消融看 R 峰质量对下游影响

**M2.3 评估集 + 黄金计划**（2-3 天）
- 从测试集抽 150-200 条（27 类分层，保证稀有类≥3 条）
- 为每条标注**黄金工具计划**（由规则生成：有节律标签→必调 R峰/HRV；QT 相关→必调 QT 工具等）+ 情境卡
- 人工抽检 20 条计划合理性

**M2.4 五维评测**（3-4 天）
| 维度 | 指标 | 方法 |
|------|------|------|
| 工具选择 | 精确率/召回率 vs 黄金计划 | 自动比对 |
| 自反思纠错 | 注入错误工具输出后的纠正率 | 注入 20% 错误 |
| 幻觉率 | LLM 声明 vs 工具输出不一致比例 | 规则 + LLM-as-judge |
| 报告辅助增益 | Agent(信号) vs Agent(信号+报告) 的 Top-5/F1 | 对照实验（B 路线数据） |
| 推理链质量 | 医学合理性 1-5 分 | LLM-as-judge + 条件允许时请医生抽评 |

**M2.5 可视化迭代**（2 天）
- `demo_pro.py` 展示：规划 → 每步工具调用（参数/输出/反思）→ 最终报告 + 标注波形

### M3：情境感知建模（3 周）⭐

**M3.1 双层输出架构**（3 天，关键设计）
- 临床诚实原则：**波形诊断不随情境变**（房颤就是房颤），**风险评估与建议随情境变**（75 岁高血压 vs 25 岁体检）
- 输出结构：
  ```json
  {
    "findings": [...],          // 情境无关：波形发现 + 证据
    "risk_assessment": {...},   // 情境条件化：风险分层 + 依据(CHA2DS2-VASc 等)
    "recommendations": [...]    // 情境条件化：建议 + 紧急度
  }
  ```

**M3.2 情境卡构造**（1 周）
- 字段：age、sex、就诊场景（急诊/门诊/体检/随访）、主诉（胸痛/心悸/晕厥/无症状）、病史（高血压/糖尿病/心衰/卒中史/房颤史）、用药
- 来源：① CinC2020 元数据（Age/Sex 已有）② 规则模板生成（医学常识约束）③ MIMIC-IV-ECG `record_list.csv` + MIMIC-IV 关联（有资质，为后续留口）
- 产物：`data/context_cards.json`，每个测试 ECG 配 3 种情境变体

**M3.3 情境注入方式**（2 天）
- 结构化 JSON 注入 Agent 系统提示/记忆（`memory.add_context`），**不**与信号混合进分类器
- 元数据编码器（Phase 3 已有）用于融合实验；提示模板增加情境渲染（`prompt_templates.py`）

**M3.4 情境敏感性基准**（1 周）⭐ 可能的论文贡献点
- 指标：同一 ECG × 3 情境 → 风险分层/建议的**变化一致性**（与医生共识模板对比）+ 变化方向正确率
- 反例测试：情境变化不应导致**波形发现**改变（防止 LLM 被情境带偏幻觉）
- 预期结果：发现层稳定 + 建议层随情境合理变化 = "情境感知"的量化证据

### M4：外部验证（2 周）

**M4.1 PTB-XL 官方协议**（3 天）
- 用 ECGFounder 官方 `ptbxl_eval.py`（150 类）在你的 PTB-XL 数据上跑，报告 150 类 macro AUC——与论文基准对齐
- 27 类 CinC2020 协议：PTB-XL 子集（strat_fold 10 为测试）上复测 ECGFounder-MLP
- ⚠️ PTB-XL 数据本身在 CinC2020 训练集里（数据源之一），报告时要注明"跨协议"与"域内"的区别

## 5. 关键技术决策与坑位清单

1. **双预处理目录并存**：`processed/`（4096，旧自训模型用）与 `processed_5k/`（ECGFounder 用）互不覆盖；新代码只写 5000 版
2. **ECGFounder 特征只算一次**：43K 条 × CPU 前向较慢，抽完特征存 npy（`data/physionet2020/ecgfounder_features/`），下游实验全部读 npy
3. **文本嵌入同样只算一次**（M1.1），训练循环里不加载 BERT
4. **防泄漏红线**：测试集文本/报告禁止进入任何训练与推理路径（B 路线"报告辅助"分支除外，且必须双组对照）；PTB-XL 按 patient 划分
5. **0.971 的历史数字**：只在论文里作为"报告辅助（oracle 上界）"出现，且必须配信号-only 对照组；对外演示时标注口径
6. **Agent 评估必须真 LLM**：废弃硬编码链路的评估数据；旧 `eval_agent.py` 结果仅作内部参考
7. **LLM 幻觉防线**：反射器规则检查（心率 20-300、QT 200-600ms、跨工具一致性 ±20bpm）+ 工具输出锚定（结论必须引用工具返回）
8. **安全**：`docs/credentials.csv`（疑似存有凭据）**禁止提交 git**，检查 `.gitignore`；API key 用环境变量
9. **NPU 经验复用**：Transformer 类结构用 FP32 + 手写 attention；CNN 可 AMP；`numpy<2`
10. **MIMIC-IV-ECG 合规**：ODbL 开放许可，但引用时须注明 PhysioNet 来源与 DOI；衍生标签集用前查许可
