## 发现清单

### 🔴-1 「左/右」方向词被列为类名停用词 → 对侧束支传导/电轴判据交叉污染（医学内容错误）

- 位置：`scripts/compile_knowledge.py:85-96`（CLASS_STOPWORDS 含 `"left"`/`"right"`）、`compile_knowledge.py:106-110`（`_text_matches` 词边界匹配）、`compile_knowledge.py:137-143`（PubMed 条目把关：condition 不匹配时回退到方向不敏感的关键词文本匹配）
- 证据（实测，非臆测）：
  1. 复现 `compile_knowledge` 关键词派生逻辑，得到：
     - `Left Bundle Branch Block` → keywords `['bundle','branch']`
     - `Right Bundle Branch Block` → keywords `['bundle','branch']`
     - `Complete Right Bundle Branch Block` → keywords `['bundle','branch']`
     - `Left Axis Deviation` → keywords `['axis','deviation']`
     - `Right Axis Deviation` → keywords `['axis','deviation']`
     即 `left`/`right` 被停用词表剥除后，左右两类只剩相同关键词，把关失去方向区分能力。
  2. 实证：`data/knowledge/raw/left_bundle_branch_block/pubmed_41429745.json` 是 RBBB 论文（title "Right bundle-branch block (RBBB) and acute coronary syndrome"，正文不含 "left bundle"）。其蒸馏条目 `condition="Right bundle-branch block (RBBB)..."`（condition 匹配=False），但因蒸馏后 `definition`/`ecg_criteria` 文本含 `bundle`/`branch`，`_text_matches=True` → 通过把关混入 LBBB 类。
  3. 结果：编译后 `classes.json` 的 `Left Bundle Branch Block` 类 `ecg_criteria` 出现 **RBBB 判据** `"rsR' pattern"`（引用 pubmed_41429745，即 RBBB 论文）、`"RBBB pattern in lead V1 (terminal R wave)"`（引用 pubmed_37321689 "Bilateral Bundle Branch Block"）。`Complete Right Bundle Branch Block` 类同理混入 LBBB/心搏过缓/晕厥等无关摘要（Syncope、LBBB、Brugada syndrome、Left bundle branch pacing）。`Left Axis Deviation` 类混入 `"Left or right axis deviation"`、`"Right axis deviation (0.9%)"`、`"Right bundle branch block morphology"`；`Right Axis Deviation` 类混入多条 `"Left axis deviation of -30..-90"` LVH 判据。
- 影响：知识库内容注入 LLM 上下文（kb_arm 评测 + web_demo），对侧束支/电轴判据被当作本类诊断特征输出，属医学内容正确性问题，可误导鉴别诊断与漏报核查。
- 修法：
  1. 从 `CLASS_STOPWORDS` 移除 `"left"`、`"right"`（以及任何承载方向/形态语义的词），保留方向词参与匹配；
  2. 对 PubMed 条目，优先以 LLM 蒸馏的 `condition`（规范病名）为把关主信号：当 `condition` 明确指向对侧诊断（如 LBBB 类遇到 condition 含 "Right bundle-branch block"）时直接剔除，而不是回退到方向不敏感的文本关键词匹配；
  3. 增加「对侧否定词」负向过滤（LBBB 类剔除文本含 "right bundle branch block" 且不含 "left bundle branch block" 的条目；RBBB 类反之），避免 "unlike LBBB, RBBB..." 这类比较句误判。

### 🟠-1 内容级缓存失效：现存 332 条蒸馏记录全部缺失 `text_hash`，重跑必全量重蒸馏并追加重复行

- 位置：`scripts/distill_knowledge.py:141-145`（`doc_key` 计算 text 哈希）、`distill_knowledge.py:148-165`（`DistillCache.__init__` 用 `e.get("text_hash","")` 回退空串；`is_done` 比较 `self.done[doc_id] == doc_key(doc)`）、`distill_knowledge.py:167-169`（`put` 以 append 追加）
- 证据（实测）：扫描 `data/knowledge/distilled/*.jsonl` 共 28 文件 332 条记录，**missing_text_hash = 332/332**。由于缓存字典以空串回退，`is_done` 对任意 doc 恒为 `"" == sha256[:16]` → False，即所有 doc 均被判定为「未完成」。
- 影响：现存数据（R4 前产物，无 text_hash）下重跑 `distill_knowledge.py` 会对全部 332 篇重调 LLM（成本/时间浪费），且 `put` 仅 append 不覆盖，同一 `doc_id` 会产生重复行；`compile_knowledge` 的 `n_sources = len(entries_sorted)`（compile_knowledge.py:222）会把重复 doc_id 重复计数，导致来源数虚增（join_list 的引用去重只在 citation 层去重 doc_id，无法修正 n_sources）。
- 修法：
  1. `DistillCache.__init__` 对 `text_hash` 缺失的历史记录视为「已完成但哈希未知」，或在 `is_done` 中当 `self.done[doc_id]` 为空串且记录存在时返回 True（不再重蒸馏）；更稳妥的是按 doc_id 做一次迁移回填 text_hash；
  2. `put` 改为「先加载、按 doc_id 覆盖后再整体写回」，或写入前检查 doc_id 是否已存在，保证幂等；
  3. 编译端 `n_sources` 改为按去重后的 doc_id 计数。

### 🟠-2 占位符过滤仅匹配精确词，24 条「短语式占位」漏入编译产物

- 位置：`scripts/compile_knowledge.py:62-70`（PLACEHOLDERS 集合 + `is_placeholder` 仅 `norm(s) in PLACEHOLDERS` 精确匹配）
- 证据（实测）：扫描 classes.json 全部字段，匹配 `not (explicitly )?(stated|mentioned|specified|provided|described)|no specific|not available|not given` 短语式占位共 **24 条**残留，例如：
  - `Complete Right Bundle Branch Block.ecg_criteria` = `"Not explicitly stated in the source"`
  - `Premature Ventricular Contractions.measurements` = `"Not explicitly stated in the source."`
  - `T Wave Abnormal.management` = `"Not stated in the source"`
  - `Nonspecific Intraventricular Conduction Disorder.management` = `"Not stated in the source."`
  - `Sinus Tachycardia.management` = `"...but specific details are not provided in the source."`
- 影响：这些是「无内容」占位，却以正常条目形态注入 LLM 上下文，浪费上下文且可能让 LLM 误读为有效判据。distill 的 SCHEMA_HINT（distill_knowledge.py:61-62）虽要求空字段用空串/空列表，但 LLM 仍输出短语变体，编译端仅做精确匹配兜不住。
- 修法：
  1. `is_placeholder` 增加正则/子串匹配：匹配 `not (explicitly )?(stated|mentioned|specified|provided|described|given)|not available|no specific|n/a|unknown` 等变体（区分「确实陈述了数值不在源中」与「整条即占位」，后者整体剔除）；
  2. 蒸馏端对占位字段做二次校验（schema 校验阶段拒绝含占位短语的字段值），从源头消除。

### 💡-2 format_entry 截断可能从引用标注中间切断，丢失来源归属

- 位置：`src/knowledge/kb_loader.py:99-102`（`text = text[:max_chars] + "\n...(截断)"` 硬截断）
- 证据：`format_entry` 先拼好含 `[来源, 等级]` 的完整文本，再按字符硬截断；若 max_chars 恰好落在某条 `- text  [pubmed(B),litfl(C)]` 的引用括号内，末尾来源标注会被截掉，违反「每条结论保留来源」的设计意图（调用方 web_demo 用 max_chars=1500、eval 用 1800，实测接近满额时易触发）。
- 建议：截断按「条目」边界进行（逐条累加长度，超限即停止并入整条或省略该条），或在截断点补 `…` 后追加「（后续条目已省略）」，避免截断引用标注。

## 阳性结论（实测验证正确的性质）

1. **检索词边界/缩写/歧义全部正确**：实测 21 组查询——`AF→Atrial Fibrillation`、`RBBB→Right Bundle Branch Block`、`CRBBB→Complete Right Bundle Branch Block`、`LAD→Left Axis Deviation`、`PVC/PAC/SVPB/VPB/NSR/STach/LQT/LPR/IAVB/IRBBB` 等缩写均正确命中；`Sinus`（4 候选）、`A`（单字母）正确返回 None；`Sinus Bradycardia`、大小写不敏感全名正确。`find` 的「精确→规范化相等→缩写→词边界」四级回退与多候选歧义返回 None 逻辑与 docstring 一致。
2. **引用完整性零缺失**：扫描 classes.json 全部 27 类的所有 citation 与 sources，`source/grade/url/doc_id` 四字段 **0 缺失**；27/27 类均有定义，27/27 定义均有 `definition_source`；sources 的 title 非空 216/216（title 缺省回退 condition，兜底有效）。
3. **Pacing Rhythm 相关性把关通过**：实测其 ecg_criteria 不含 Brugada/LQTS/arrhythmogenic/Interatrial block 等污染关键词（verify_r4_kb.py [6] 断言通过），且该类 n_sources=3、定义来自 LITFL 对口页，方向/节律停用词在该类未造成污染。
4. **general 正/负词表过滤有效**：general 类 20 个来源全部为 ECG 相关（ecgpedia 基础页 + ECG 方法学/间期/形态 PubMed 摘要），导管/十二指肠/胎儿/TDI 超声等无关内容已被 GENERAL_NEG 剔除；general 定义正确取自 ecgpedia Conduction 页（source_rank 教育页优先生效）。
5. **引用标题透传（3E-Y7）与教育页优先选取（2F-1）生效**：LITFL/ECGpedia 来源的 `title` 为真实页标题（如 "Complete Right Bundle Branch Block (RBBB)"、LAD/RAD 均标注 ecg-axis-interpretation 真实页），且各病种 `definition` 一律优先教育页（litfl/ecgpedia）而非 PubMed 摘要。
