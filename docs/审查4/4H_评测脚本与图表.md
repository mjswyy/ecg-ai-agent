## 发现清单

### 🟠-1 共享指标模块 evaluate() 的 mAP 仍用 average="macro"（空正类按 0 计入，系统性拉低），与 trainer.evaluate() 口径冲突
- 位置：`src/evaluation/metrics/classification.py:105`（对比 `src/ecg_models/trainer.py:510-518`）
- 证据：
  - `classification.py:105`：`mAP = float(average_precision_score(labels, probs, average="macro"))`——该模块 docstring 声称是"分类指标统一入口…保证口径一致"。
  - `trainer.py:510-518` 明确注释"第三轮审查 3C-TRAIN-3：与 macro_auc 口径一致——仅对 0<sum<len 的类别计算 AP 后取平均（旧版 average='macro' 把无正样本类按 0 计入，系统性拉低）"，并已改为逐类过滤。即共享模块里保留了 trainer 已修掉的同一个 bug。
  - 实测（read-only）：构造 3 类、第 3 类全为负，`average_precision_score(y,p,average='macro')` 返回 0.6667（=均值[1.0,1.0,0.0]）并报 `UserWarning: No positive class found in y_true`，而正确口径应为 1.0。
  - 现役测试集 27 类均有正样本（per_class_auc.json 最小 n_positive=23），故 metrics.json 的 mAP=0.5822 未被触发；但 per_source 分析中 st_petersburg_incart 仅 2 个活跃类、ptb 仅 7 个活跃类，若有人对该子集调用 `evaluate()`，25 个空类会把 mAP 拖向 0。
- 修法：将 `evaluate()` 的 mAP 改为与 `trainer.evaluate()` 一致——逐类 `if 0 < labels[:,c].sum() < len(labels)` 后取 `np.mean(ap_per_class)`，或直接复用同一实现。

### 🟠-2 eval_mimic_domain.py 的"平导联/信号质量"在 z-score 归一化之后统计，且 quality_vs_confidence 静默不产出
- 位置：`scripts/eval_mimic_domain.py:103-106`（质量统计）、`179-185`（静默跳过）、`107-113/127-133`（flat 判定）
- 证据：
  - `103-106`：先 `norm = p5.official_zscore(seg, pl, pr)`，再 `flat = (norm.std(axis=1) < 0.05).sum()`——flat 判定作用于归一化后的信号。`preprocess_data_5k.py:156-172` 显示 z-score 是"全信号合并单标量 mean/std"，归一化后仅"恰好常量"的导联 std 才会 <0.05，真实低幅/噪声导联被拉伸后不再判为"平导联"。
  - 产物 `outputs/external_eval/mimic_domain.json`：mimic `signal_quality.mean_flat_leads=0.002, n_all_flat=0`；cinc `mean_flat_leads=0.014, n_all_flat=1`——与脚本 docstring 声称的"MIMIC 含真实临床噪声"、要做的"[3] 信号质量 vs 置信度（平导联/噪声鲁棒性）"不符。
  - `179-185`：`clean=flat_idx<=2` 后 `if clean.sum()>0 and (~clean).sum()>0` 才写 `quality_vs_confidence`；因 degraded 组为空，该条件恒 False，产物里根本没有 `quality_vs_confidence` 键，且脚本无任何告警——静默省略了声明要做的分析。
- 修法：flat/质量判定应在 `official_zscore` 之前（对 `filt` 或 `seg` 的原始幅值）计算；当 degraded 组为空时显式写 `"quality_vs_confidence": null` 并 logger.warning 说明无法进行该分析，禁止静默缺失。

- 位置：`scripts/make_figures.py:39-48`
- 证据：
  - `40-47`：8 个历史数值硬编码（0.590 / 0.791 / 0.808 / 0.822 / 0.841 / 0.850 / 0.905）。其中 `xResNet1D-101=0.791、ECG Transformer=0.808、2模型集成=0.822` 标注为"从零训练"，与 InceptionTime/SimCLR/3模型/线性探针 的"旧标签体系·历史"标注不同。
  - 这三根柱实际有磁盘产物：`outputs/comprehensive_eval.json` 的 `macro_auc` = 0.7907594857 / 0.8081794658 / 0.8223592710（= 0.791/0.808/0.822 四舍五入），由 DEPRECATED 的 `eval_comprehensive.py`（`data/physionet2020/processed`，记录级旧划分）生成。因此 `37-38` 注释"历史行（无磁盘产物）"对这三根柱不成立，且三根"从零训练"柱与现役 MLP 柱（`outputs/ecgfounder_mlp/metrics.json` macro_auc=0.9456，患者级 n=3,754）不是同一标签体系/划分，仅靠 `66-67` x 轴文字提示"历史柱: 旧标签体系/记录级"，柱身标注"从零训练"未携带该口径告警。
  - 其余 5 个数值（0.590/0.841/0.850/0.905）在 outputs/ 下确无对应产物，属纯硬编码。

### 🟡-2 阈值准则跨脚本不一致：Youden vs argmax-F1（历史脚本与现役路径口径不统一）
- 位置：`src/evaluation/metrics/classification.py:48-59`（Youden，J=TPR−FPR）、`scripts/eval_comprehensive.py:48-60`（Youden）、`scripts/eval_per_class.py:17,55`（Youden）、`scripts/eval_per_source.py:21`（Youden） 对比 `scripts/eval_ensemble.py:94-97`（argmax-F1 阈值）、`src/ecg_models/trainer.py:480-484`（argmax-F1 阈值）
- 证据：背景与模块 docstring 均定"逐类 Youden 阈值取自验证集"；现役 MLP 路径（classification/youden_thresholds + eval_per_class/eval_per_source）统一用 Youden，但 DEPRECATED 的 `eval_ensemble.py` 与 `trainer.evaluate(fit_thresholds=True)` 用 precision_recall_curve 上 argmax-F1 选阈值。两种准则给出不同阈值 → F1 不可直接横向比较（均为验证集定阈值、无泄漏，但准则不同）。
- 修法：统一阈值准则为 Youden（或至少在 deprecated 脚本头注明"F1 阈值口径，与现役 Youden 不可比"）。

### 💡-1 macro_auc_with_ci 点估计与 bootstrap 的类过滤口径不同（理论偏差，本数据集实际无影响）
- 位置：`src/evaluation/metrics/classification.py:25-45`
- 证据：点估计 `macro`（`27-29`）按**原始**标签过滤 `sum==0 or sum==len`；bootstrap（`37-41`）按**重采样后**标签过滤。两者纳入平均的类集可能不同。本数据 n=3,754、最稀类 n=23，重采样中某类变全 0/全 1 概率 ≈ e^-23 可忽略，故不影响现数字；但作为通用模块存在理论口径差。
- 修法：bootstrap 内对类采用与点估计相同的"原始标签是否 0<sum<len"过滤，使分布与点估计同域。

### 💡-2 topk_hit_rate 在循环内自减 total（可读性陷阱，功能等价）
- 位置：`scripts/eval_comprehensive.py:63-74`、`scripts/eval_topk.py:30-42`、`scripts/eval_ecgfounder.py:118-125`
- 证据：`for i in range(total)` 的 range 在进入循环时即求值，循环内 `total -= 1` 不影响迭代次数，仅让返回分母排除空样本——与 `classification.topk_hits`（`total += 1`）等价但易误读为"跳过样本"。
- 修法：改用 `classification.topk_hits` 或显式 `denom` 变量，删除自减写法。

### 💡-3 fig_context_matrix 的 urg_map/risk_map 含死键，-1（缺失）值无图例

- 修法：删除死键；在 colorbar 增加 -1 刻度/标签（如"缺失/未评估"）。

### 💡-4 eval_ensemble.py 阈值回退分支为死代码
- 位置：`scripts/eval_ensemble.py:97`
- 证据：`best_thresh = float(thresh[best_idx]) if len(thresh) > best_idx else 0.5`——`f1_curve` 长度 == `len(thresh)` == `len(prec)-1`，故 `best_idx < len(thresh)` 恒成立，`else 0.5` 永不触发。

### 💡-5 eval_comprehensive.py 的 bootstrap_auc_ci 以 bootstrap 均值冒充"macro_auc"
- 位置：`scripts/eval_comprehensive.py:32-45`（返回 `mean`）
- 证据：`bootstrap_auc_ci` 返回 `(mean_of_bootstraps, lo, hi)`，`188` 将其存为 `"macro_auc"`；产物 `comprehensive_eval.json` 的 `macro_auc=0.7907594857` 实为 1000 次 bootstrap 宏 AUC 的均值，而非全量测试集点估计（二者可有小幅差）。deprecated 但数字被成绩单沿用。
- 修法：`macro_auc` 用全量点估计（`macro_auc(labels_test, probs)`），CI 单独由 bootstrap 给出。

### 💡-6 eval_per_class.py 混淆对注释"假阳性"与代码"漏报（假阴性）"不符
- 位置：`scripts/eval_per_class.py:73-88`
- 证据：`80` `missed = (y[:,c]==1) & (pred[:,c]==0)` 统计的是类 c 的**假阴性（漏报）**样本被误判为 c2 的次数，而 `73` 注释与 `74` 打印标题写"假阳性样本/假阳性竞争类"。产物 `top_confusion_pairs`（如 "Sinus Rhythm->T Wave Inversion"）实为漏报去向，非假阳性。
- 修法：注释/标题改为"漏报去向（假阴性竞争类）"。

### 💡-7 fig_radar "抗幻觉率=1.0" 来自 0/99 声明的小样本，且 rep_q 存在软默认 0.5
- 位置：`scripts/make_figures.py:109-113`
- 证据：`metrics_main.json` 的 `hallucination={"n_claims":99,"n_hallucinated":0,"rate":0.0}`，`110-111` 得 `hallu=1.0`——雷达画满格"抗幻觉率 1.0"，但仅 99 条声明、0 幻觉，样本极小，视觉上易过度承诺（`109` 注释只修了 `rate=None` 的 N/A 情形，未处理 `rate=0.0` 小样本）。`113` `rep_q=(...total.mean..., 2.5)/5.0` 的默认 2.5/5.0=0.5 在缺 arm 检查已保证 main 存在后仍可能因缺 `total/mean` 键静默取 0.5。

## 阳性结论（实测验证正确的性质）

1. **全量编译通过**：14 个文件 `py_compile` 全部 OK，无语法错误。
2. **bootstrap 可复现**：`macro_auc_with_ci` 用 `RandomState(42)`，同输入两次调用输出完全一致；点估计宏 AUC 与逐类 `roc_auc_score` 直接平均一致。
3. **现役 MLP 数字跨产物一致**：`outputs/ecgfounder_mlp/metrics.json` 的 macro_auc=0.9456、CI=[0.9393,0.9519] 与 `outputs/external_eval/per_source_auc.json` 的 `overall`（n=3754, 0.9456, [0.9393,0.9519]）完全一致；n=3754 与背景"患者级测试集 3754"吻合。
4. **阈值来源正确（现役路径无测试集拟合泄漏）**：`classification.youden_thresholds` 在 `eval_per_class.py:51-55` 用 VAL_FEAT/VAL_LABEL（验证集）定阈值后评估测试集；`evaluate()` 未传 thresholds 时实测会告警并回退 0.5（2E-O7 行为确认），不在评估集现算 Youden。
5. **小样本退化已在脚本层面标注**：`eval_per_source.py:80-83` 对 n<50 源打印"⚠️ 样本过少，仅参考"，且其注释预测的 n=2→[0.5,0.5]、n=7→[1.0,1.0] 与产物数字精确吻合（见 🟡-1，仅产物未持久化该标注）。
6. **make_figures 主要数据源已磁盘化/防伪造**：MLP 柱从 `outputs/ecgfounder_mlp/metrics.json` 读取（非硬编码）；`fig_radar` 缺臂时 `raise SystemExit` 显式报错（`96-100`）；`fig_context_matrix` n 动态取 `len(recs)`（实测 records.jsonl=40 条，与代码注释一致），不再硬编码 n=36。
7. **成绩单历史数字非凭空捏造**：0.791/0.808/0.822 可精确追溯到 `outputs/comprehensive_eval.json`（0.7908/0.8082/0.8224 四舍五入）。
8. **配套常数一致**：`ecgfounder_tasks.txt` 实测 150 行，与 `eval_mimic_domain.py` 的 `n_classes=150`、`minlength=150` 一致。
9. **agent_eval 三臂为待重跑中间态（一句话确认）**：`judge_rubric_results.json` 中 main n=58 / report_arm n=71 / kb_arm n=58（均 <130，且 main judge_failures=12），与任务背景"main/report 臂 n<130 中间态"一致，`fig_radar` 直接照此读取并如实显示 n=58，未伪造。
