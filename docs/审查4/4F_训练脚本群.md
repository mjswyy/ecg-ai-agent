### 🟠-1 CLIP 训练的"双保险"红线检查仅告警、不拦截（拆分不一致时仍可能把错分记录用于训练）
- 位置：scripts/train_ecg_text_clip.py:110-114
- 证据：
  ```python
  if report_splits.get(rid, "unknown") != split:
      logger.warning(f"[红线] {rid} 报告 split={report_splits.get(rid)} != manifest {split}")
  feats.append(i)   # 即便 split 不一致，仍然把该对加入训练/验证对
  ids.append(rid)
  ```
  注释（line 110）自称"双保险"，但实现上不一致时只打 warning，随后无条件 `feats.append(i)`。若 `report_splits.json` 与 manifest 的划分出现不一致（这正是该检查要防的场景），该记录仍会被当作 `split`（例如 train）样本参与训练/检索，红线没有实际约束力。
- 修法：不一致时应 `continue` 跳过该记录（或用 `logger.error` + 计数统计后强制 `sys.exit`），使双保险真正生效；至少要在 meta.json 里落盘不一致条数，供事后审计。

### 🟡-2 train_multimodal.py 融合层关键字 `nhead` 与签名 `num_heads` 不一致（即使恢复依赖也会 TypeError 崩溃）

### 🟡-4 mAP 口径不一致：主结果脚本与 canonical 指标用 `average="macro"`（零正类被计为 0，系统性拉低），而 trainer 已修复为跳过退化类
- 位置：scripts/train_ecgfounder_head.py:108、src/evaluation/metrics/classification.py:105（未修复侧）；src/ecg_models/trainer.py:510-518（已修复侧）
- 证据：`train_ecgfounder_head.py:108` 与 `classification.py:105` 均为 `mAP = average_precision_score(labels, probs, average="macro")`。实测（3 类，第 3 类 0 正样本）：
  ```
  per-class AP = [0.6573, 0.6482, 0.0]     # 零正类被 sklearn 记作 AP=0.0
  macro = 0.4352                           # 含零正类
  跳过零正类的均值 = 0.6527                # 与 trainer 的 skip 口径一致
  ```
  trainer.py:510-511 的注释明确承认"旧版 average='macro' 把无正样本类按 0 计入，系统性拉低"，并已在 trainer 侧改为 `0 < sum < len` 跳过。但产出论文数字的 head 脚本（其本地 `evaluate`）与 canonical `classification.py` 仍未同步。方向是**保守低估**（非虚高），是否实际影响取决于 test 集是否所有 27 类都有正样本；但同一指标在仓库内存在两套口径。

### 🟡-5 ECGTrainer 的 fit 阈值是 F1-max（precision_recall_curve）而非文档宣称的 Youden，与协议描述不一致
- 位置：src/ecg_models/trainer.py:480-486（消费方：scripts/train_backbone.py:196-197、scripts/train_ecgfounder_ft.py:142-143、scripts/train_simclr.py:183-184）
- 证据：trainer.evaluate(fit_thresholds=True) 用 `precision_recall_curve` 取 `argmax(2·prec·rec/(prec+rec))`（F1 最大阈值），不是 `roc_curve` 的 Youden J。而项目背景与多处注释宣称"逐类 Youden 阈值取自验证集"。主结果脚本 train_ecgfounder_head.py 用本地 `youden_thresholds`（Youden）→ 论文数字不受影响；但经由 ECGTrainer 的三个脚本（train_backbone/simclr/ft，均已废弃）实际用的是 F1-max 阈值，与"逐类 Youden"协议描述背离。
- 修法：二选一——将 trainer 的 fit_thresholds 改为 Youden（`roc_curve` + `argmax(tpr-fpr)`），或在该接口 docstring 明示"fit 内部阈值为 F1-max，非 Youden"，并区分与论文协议的关系。

### 💡-3 train_multimodal_fair.py 重建 CLIP 投影头时硬编码输入维 1024

### 💡-4 train_multimodal_fair.py 元数据解析：字符串型年龄被静默判为"未知"
- 位置：scripts/train_multimodal_fair.py:50
- 证据：`age_norm = float(age) / 100.0 if isinstance(age, (int, float)) else -1.0`。若 manifest 的 `age` 以 JSON 字符串（如 `"57"`）存储，`isinstance` 判定为 False → 全部 age 归一化为 -1.0（未知），C/C2/D/D2 变体将丢失年龄特征，且仅有一条"缺元数据比例"日志间接暴露（line 167 用 `mf[:,0] < 0` 统计）。是否触发取决于 manifest 中 age 的实际类型。
- 修法：解析时对数值字符串做 `float()` 兜底（try/except），或在该脚本入口对 age 类型做一次性断言并提示。

### 💡-5 train_ecg_text_clip.py 无设备参数，恒定 CPU 训练
- 位置：scripts/train_ecg_text_clip.py:68-78
- 证据：整个脚本没有 `--device`，模型/张量从不 `.to(device)`。对 30K×1024 缓存特征的投影头训练可完成，但在有 GPU 的环境不会自动利用。

## 阳性结论（实测验证正确的性质）

1. **泄漏红线（对比预训练）已落实**：`ECGContrastiveDataset` 默认 `split="train"`，有 manifest 时按 `train_manifest.json` 精确取 train 记录（dataset.py:191、200-207）；train_backbone.py:122-126、train_simclr.py:92-96 均未传 split → 默认 train。无 manifest 时才回退全盘扫描，且打了明显告警（dataset.py:209-211）。
2. **CLIP 训练对只取 train 划分**：`build_pairs("train")` 只遍历 `ecg_ids["train"]`（train_ecg_text_clip.py:103-120），val 对仅用于检索评估，test 对仅统计不参与（line 120）。
3. **阈值来源正确（无测试集现算）**：主结果脚本在 val 上 `youden_thresholds(y_val, val_probs)` 后仅对 test 应用（train_ecgfounder_head.py:232-238）；经 ECGTrainer 的三脚本均传 `thresholds=trainer.val_thresholds`（train_backbone.py:196-197、train_ecgfounder_ft.py:142-143、train_simclr.py:183-184），trainer 内部在验证集上 `fit_thresholds=True` 定阈值并快照。
4. **best_state 兜底齐全**：train_ecgfounder_head.py:189-192、train_multimodal_fair.py:119-121、train_ecg_text_clip.py:162-163 均对 `best_state is None` 回退最后一轮权重；trainer.py:405-409 在 best_state 存在时回填 best 权重**与对应 val 阈值快照**（口径一致）。
5. **缺权重不再静默随机初始化**：train_simclr.py:137-147 `--skip-pretrain` 但 `pretrain_path` 不存在时 `logger.error` + `sys.exit(1)`（原为静默随机初始化继续微调）。
6. **加载安全统一**：所有 checkpoint 加载走 `safe_torch_load`（train_ecgfounder_ft.py:41、train_multimodal.py:53/318、train_simclr.py:141、train_multimodal_fair.py:192），`safe_load.py` 用 `weights_only=True` + numpy 白名单（`add_safe_globals`），失败仅对可信来源回退 `weights_only=False`。
7. **标签平滑口径一致（实测）**：head/fair 脚本手动 `y*0.9+0.05` 与 trainer 的 `labels*(1-ε)+0.5*ε`（ε=0.1）结果完全一致（实测 `[0.95, 0.05]` 两路相等）。
8. **InfoNCE 负样本掩码正确（实测）**：每行排除自身与正样本对，留 2B-2 个负样本（实测 mask row0 恰 2 个 True、负样本 6=2B-2），且温度只在相似度矩阵处除一次（trainer.py:199-238）。
9. **CLIP 检索是真正的跨模态（实测）**：`retrieval_recall` 用文本查询在 ECG 键里找匹配 id；随机嵌入实测对角并非恒 rank-1，证明评估非平凡；`retrieval_recall` 实现（classification.py:119-143）对未出现在键集内的查询正确跳过。
10. **早停语义正确**：trainer.py:400 `early_stopping_patience > 0` 才启用（patience=0 不再误停），min_delta=1e-4；train_multilabel 与 head/fair 脚本的早停逻辑一致。
11. **8 个脚本 `python -m py_compile` 全部通过（EXIT=0）**，无语法错误。
