## 发现清单

### 🔴-1 safe_load 加载失败时自动回退 weights_only=False，使“安全加载”形同虚设（任意 pickle 代码执行风险）
- 位置：src/utils/safe_load.py:68-73
- 证据：`safe_torch_load` 默认 `weights_only=True`，但 `except Exception` 分支无条件 `torch.load(path, ..., weights_only=False)`。实测（BytesIO，不落盘）：
  ```
  weights_only=True RAISED: UnpicklingError Weights only load failed...
  fallback weights_only=False loaded: dict ['x', 'a']
  ```
  `weights_only=False` 即完整 pickle 反序列化，恶意检查点（如含 `__reduce__` 载荷）会在此执行任意代码——这恰恰是本模块声称要防范的攻击。任何导致 weights_only 路径失败的原因（恶意对象、未覆盖的全局）都会静默降级到不安全加载，且仅打印 warning 后继续。
- 修法：默认不自动回退。改为 `weights_only=False` 必须显式传入（如 `safe_torch_load(path, weights_only=False)`），或仅当 `map_location` 明确标注为可信源（白名单路径/显式 `allow_unsafe=True` 参数）时才回退；回退前应抛异常或要求调用方确认。

### 🟠-2 白名单未覆盖 numpy 2.x 标量全局名 `numpy._core.multiarray.scalar`，numpy 2.x 保存的含标量实例的检查点仍失败并触发 🔴-1 回退
- 位置：src/utils/safe_load.py:22-35、47
- 证据：`_NumpyScalarShim.__module__` 被设为 `"numpy.core.multiarray"`（numpy 1.x 名），`__qualname__="scalar"`。实测当前 numpy 2.1.3 下 `np.float64(3.0).__reduce__()` 返回的全局是 `numpy._core.multiarray.scalar`；`register_safe_globals()` 后 `torch.load(weights_only=True)` 仍报 `UnpicklingError: GLOBAL numpy._core.multiarray.scalar was not an allowed global`。`torch.serialization.get_safe_globals()` 实测注册键仅含 `numpy.core.multiarray.scalar`（1.x 名），无 `_core` 变体。
- 修法：同时注册 `numpy._core.multiarray.scalar`（或直接 `add_safe_globals([numpy._core.multiarray.scalar])`），使 numpy 1.x（`numpy.core.multiarray.scalar`）与 2.x（`numpy._core.multiarray.scalar`）两种 pickle 名都能命中。注意：官方 ECGFounder ckpt 若确为 numpy 1.x 保存，shim 名字匹配是设计意图；本发现针对 numpy 2.x 重存/新存检查点。

### 🟠-3 SupConLoss 在无正样本对时产生 NaN（batch=1 或全批标签互异）
- 位置：src/context_modeling/contrastive/losses.py:116-117
- 证据：`loss = -torch.log(pos_sum / (pos_sum + neg_sum + 1e-8)); return loss[pos_sum > 0].mean()`。当所有行的 `pos_mask` 均为 False（batch=1，或每个样本标签唯一）时，`loss` 张量为空，`mean()` 返回 NaN。实测：
  ```
  all-distinct labels loss -> nan (isnan True)
  batch1 loss -> nan (isnan True)
  ```
  当前无脚本 import SupConLoss（grep 确认仅定义处出现），故为潜在缺陷而非在役故障。
- 修法：`pos = pos_sum > 0; return loss[pos].mean() if pos.any() else torch.zeros((), device=...)`；或在构造时校验 batch 内存在正对，否则跳过该步/返回 0。

### 🟠-4 get_device_object 对显式设备索引（"cuda:N"/"npu:N"）静默回退 CPU
- 位置：src/utils/device_utils.py:67、88-94
- 证据：`detect_device("cuda:0")` 走不到 `== "cuda"` 分支（line 64），直接 `return device_str`（line 67）；`get_device_object` 仅匹配 `"npu"`/`"cuda"`，其余 `else` 返回 `torch.device("cpu")`。实测：
  ```
  detect cuda:1 -> 'cuda:1'
  get_device_object cuda:1 -> cpu
  get_device_object cuda:0 -> cpu
  ```
  多卡用户传 "cuda:1" 会静默在 CPU 上训练/推理，无告警。
- 修法：`get_device_object` 对以 `cuda`/`npu` 开头且带索引的字符串解析 `torch.device(device_str)`；或在 `detect_device` 中对 `cuda[:N]`/`npu[:N]` 前缀做归一化校验。

### 🟡-5 TextEncoder 占位路径维度硬编码 768 且占位张量无 device
- 位置：src/context_modeling/text_encoder.py:45、95-98
- 证据：`self._output_dim = 768` 在加载前硬编码；若 `transformers` 未安装或加载失败（line 56-61），`_output_dim` 恒为 768，即使请求的是非 768 维模型也返回错误维度零张量；且 `_placeholder_encode` 返回 `torch.zeros(...)`（无 `device=`），当 `TextEncoder(..., device=cuda)` 且加载失败时，占位张量在 CPU，与下游设备不一致。
- 修法：占位路径按 `model_name` 的预期 hidden_size 或显式参数设置 `_output_dim`；`_placeholder_encode` 使用 `self.encoder` 占位设备或统一 `device` 参数，并 `torch.zeros(..., device=...)`。

### 🟡-6 TextEncoder max 池化用 0 掩码，全负 hidden 时会被 padding 的 0 污染
- 位置：src/context_modeling/text_encoder.py:90
- 证据：`max` 池化 `(last_hidden_state * mask).max(1).values` 用 0 掩 padding，若某样本所有有效 token 的 hidden 值均为负，padding 位置的 0 会成为最大值，返回错误的 0 向量。BERT 隐藏层常含负值，属真实风险。当前活跃脚本（extract_text_embeddings.py:52、train_multimodal.py）均用 `pooling="mean"`，`max` 路径暂未使用。
- 修法：max 池化改为 `masked_fill` 一个足够负的常数（如 `-1e9`）再取 max，或直接采用 mean/CLS。

### 🟡-7（离线·不可达）MetadataEncoder age=None 时维度错配
- 位置：src/context_modeling/metadata_encoder.py:87、100、105
- 证据：当 `age=None, sex=None, source=["a","b",...]` 时，`batch_size` 停在 1（line 87），sex 分支产生 `(1, sex_dim)`（line 95），source 分支按 `len(source)` 产生 `(N, source_dim)`（line 100-101），`torch.cat(features, dim=-1)`（line 105）在 batch 维不匹配 → RuntimeError。该模块顶部 `raise RuntimeError`（line 23）使 import 即失败（实测确认），缺陷不可达，仅作历史记录。
- 修法：（若恢复）source 分支按 `batch_size` 展开，或从 source 长度推导 batch_size 并校验三者一致。

### 🟡-8（离线·不可达）CrossAttentionFusion 构造参数 `num_heads` 与旧调用方 `nhead=` 不匹配
- 位置：src/context_modeling/fusion/cross_attention.py:29 vs scripts/train_multimodal.py:80
- 证据：`CrossAttentionFusion.__init__` 仅接受 `num_heads`；而（已废弃的）train_multimodal.py:78-81 以 `CrossAttentionFusion(..., hidden_dim=256, nhead=8, ...)` 调用，会 `TypeError: unexpected keyword argument 'nhead'`。该模块同样 import 即 raise（line 10），train_multimodal.py 自身也在 line 27 import 时崩溃，故双重不可达。
- 修法：（若恢复）统一参数名为 `num_heads` 或增加 `nhead` 别名兼容旧调用。

### 🟡-9（离线·不可达）VQ-VAE perplexity 恒为 1，无法反映 codebook 利用率
- 位置：src/context_modeling/ecg_tokenizer.py:66
- 证据：perplexity 由 one-hot 编码的逐样本熵计算：`torch.exp(-sum(one_hot * log(one_hot+1e-10)) / B)`。one-hot 向量熵恒为 0，故 perplexity ≈ exp(0) = 1 恒定。实测公式复现：`computed perplexity = 0.9999999991999999`。正确做法应基于整批 codebook 使用频率分布 `p_j = count(j)/(B*L)` 计算 `exp(-sum(p_j log p_j))`。模块 import 即 raise（line 29），不可达。
- 修法：（若恢复）改为批次级 codebook 使用频率熵。

### 🟡-10（离线·不可达）MultimodalModel 将文本作为推理输入，违反“推理时 signal-only”红线（历史设计）
- 位置：src/context_modeling/multimodal_model.py:88-94、102
- 证据：`forward` 中 `text_feat = self.text_encoder(texts)` 直接送入 fusion→classifier，文本（报告内容）参与分类推理；与“文本嵌入只作监督、不做推理输入”的防泄漏红线冲突。该模块 import 即 raise（line 18），已下线，属历史记录；现役公平版（train_ecg_text_clip.py / train_multimodal_fair.py）文本仅作监督。
- 修法：无需修复（已下线）；如恢复需按公平消融口径将文本仅用于监督分支，并保持双组对照。

### 💡-11 ECGTextCLIP.encode_text 的 if/else 两分支完全相同
- 位置：src/context_modeling/contrastive/ecg_text_clip.py:90-93
- 证据：`if isinstance(texts,(list,tuple)): features = self.text_encoder(texts)` 与 `else: features = self.text_encoder(texts)` 分支体一致，为冗余代码（该模块也已下线）。
- 修法：删除分支，直接 `features = self.text_encoder(texts)`。

### 💡-12 device_utils 仍使用已废弃的 torch.cuda.amp.autocast
- 位置：src/utils/device_utils.py:134-147
- 证据：`autocast = torch.cuda.amp.autocast`（实测当前环境 `autocast <class 'torch.cuda.amp.autocast_mode.autocast'>`），在 torch 2.4+ 已废弃（FutureWarning），仅因 `torch.amp.autocast` 需 `device_type` 位置参数而保留（注释 3C-AMP-1 已说明）。非缺陷，但可统一。
- 修法：封装 `torch.amp.autocast(device_type=..., enabled=...)` 的薄适配器，消除告警并统一 NPU/CUDA 调用。

### 💡-13 SupConLoss 温度未做下界保护
- 位置：src/context_modeling/contrastive/losses.py:77-79、96
- 证据：`self.temperature` 为普通 float（非可学习参数，无漂移风险），但未校验 >0；若传入 `temperature<=0`，`sim = ... / self.temperature` 产生 inf/NaN。默认 0.07 下 `sim` 最大 ≈14.3，`exp` ≈1.6e6 不溢出（float32），数值稳定。
- 修法：构造时断言 `temperature > 0`，或与 InfoNCELoss 一致采用 logit_scale 形式。

## 阳性结论（实测验证正确的性质）

1. **InfoNCELoss 数值正确且稳定**：`logit_scale = log(1/T)` 初始化正确（实测 T=0.07 → logit_scale=2.6593，temperature 属性回读 0.07）；前向先 `clamp` 到 `[ln(1/100), ln(100)]` 再 `exp`，温度等价约束在 [0.01, 100]，无 NaN/溢出；对称双向 CE（`loss1` 按行、`loss2` 按 `logits.T`）与对角线标签 `torch.arange(B)` 均正确；实测随机输入 loss=0.529 且 `isfinite=True`。
2. **SupConLoss 负样本掩码正确**：`neg_mask = (~pos_mask).fill_diagonal_(False)` 已剔除自身，避免 `exp(sim[i,i])=exp(1/τ)` 主导分母；多标签正对 `labels @ labels.T > 0` 逻辑正确。
3. **废弃模块下线护栏有效**：7 个遗留模块（ecg_text_clip / ecg_tokenizer / cross_attention / gated_fusion / late_fusion / metadata_encoder / multimodal_model）顶层 `raise RuntimeError`，实测 `importlib.import_module` 全部抛 RuntimeError；`fusion/__init__.py` 不再导出任何符号，防止误用。
4. **device_utils 设备检测与 AMP 后端选择正确**：`detect_device("auto")` 在无 NPU/CUDA 环境正确返回 "cpu"（实测）；AMP 优先 NPU、回退 CUDA（实测 GradScaler=torch.amp.GradScaler、autocast=torch.cuda.amp.autocast）、CPU 回退 `_DummyGradScaler/_DummyAutocast`；`_Dummy*` 接口完备（scale/unscale_/step/update/__enter__/__exit__）。
5. **safe_load 白名单注册幂等且基本有效**：`register_safe_globals()` 幂等（`_WHITELIST_REGISTERED` 守卫）、无异常（实测注册成功）；`np.dtype`、`np.ndarray`、`np.float64`（类型）、`numpy.dtypes.*DType` 在 weights_only=True 下可加载（实测 dtype/ndarray 加载 OK）。
6. **文本泄漏红线在活跃链路中受控**：TextEncoder 仅编码文本为嵌入；现役 `train_ecg_text_clip.py` 使用缓存文本嵌入，训练对仅取 train 划分、test 完全不参与（脚本内红线检查）、文本只作对比监督；InfoNCELoss 本身不构成推理输入。
7. **torchvision_stub 幂等且安全**：`install()` 由 `_STUBBED` 守卫幂等；真实 torchvision 可导入时直接让位（line 46-48）；桩仅提供 transformers 导入所需符号，图像函数抛 RuntimeError 明确报错。
