## 🔴 确认缺陷（影响正确性/数据完整性/论文结论）

### 🔴-1 LabelExtractor 的 27 类映射与官方 PhysioNet 2020 评分类不符，且多个"类别名 ↔ SNOMED 码"语义错配

- **位置**：`src/data_pipeline/label_extractor.py:36-69`（CHALLENGE_CLASSES 定义）、`:77-102`（SNOMED_CT_EQUIVALENTS 等价映射）、`:121`（按代码排序建索引）

### 🔴-2 train/val/test 划分为记录级而非患者级，存在患者泄漏（PTB-XL 实测 546 名患者同时出现在 train 与 test）

- **位置**：`scripts/preprocess_data.py:146-162`（旧版划分，按 source 内记录随机置乱 70/15/15）；`scripts/preprocess_data_5k.py:214-225`、`:325-344`（完全复用旧划分，注释自称"防泄漏"，实为继承同一缺陷）
- **问题描述**：划分按"记录"置乱，未按患者分组。PhysioNet 2020 中 PTB-XL 存在大量患者多记录（本库 `data/physionet2020/ptbxl_database.csv` 实测：18869 名患者中 2111 名有多条记录）。同一患者的多次心电图被随机分入 train/val/test。
- **验证（实测）**：用 `ptbxl_database.csv` 的 `ecg_id → patient_id` 关联 manifest：
  - train∩test 患者重叠：**546**；train∩val：525；val∩test：162；三个划分同时出现：72。
  - 例：patient 509.0、10750.0、16637.0 等同时出现在 train 与 test。
- **影响**：测试指标被同患者（同解剖、同病程，PTB-XL 中多记录常为同次事件短间隔重录）的训练记录抬高，属划分泄漏红线，直接影响论文结论的可靠性。PTB-XL 官方基准惯例要求患者级划分。
- **建议修法**：基于 `ptbxl_database.csv` 的 `patient_id` 做患者级划分（grouped split），其余无患者 ID 的数据源保持记录级；重划后需同步重跑 preprocess_data_5k（manifest 复用逻辑）。

## 🟠 潜在缺陷（特定输入/边界触发）

### 🟠-1 时间扭曲增强在 scale<1 时产生长达 20% 窗口的常量平台伪影

- **位置**：`src/data_pipeline/augmentor.py:191-223`（`apply_time_warp`，核心 `:213-221`）
- **问题描述**：`warped_positions = orig_positions * scale` 后以 `interp1d(warped, y, bounds_error=False, fill_value=(y[0], y[-1]))` 在 `orig_positions` 上求值。scale<1 时 warped 最大坐标 = (L-1)·scale < L-1，超出部分全部填充为**常数 y[-1]**，形成尾部长平台。docstring（`:195`）声称"边界值填充（而非外推）防止产生伪影"，实际该填充本身就是大伪影。
- **验证**：合成 5000 点信号，scale=0.8 → 输出尾部 **1000/5000 点（20%）为常量**；scale∈[0.8,1.2] 均匀采样时平均约 5-10% 平台。代码路径已实测复现。
- **影响面**：`time_warp` 默认开启（`:51`），`train_backbone.py:111`（apply_prob 默认 1.0，即**每个**训练样本都过全部增强）、`train_simclr.py:94/146`、`train_ecgfounder_ft.py:108`（apply_prob 0.8）均使用默认构造。模型可能学到"尾部常量=正常"，污染训练分布。
- **建议修法**：将 warped 坐标平移到窗口中心（`warped -= (scale-1)*(L-1)/2`）再插值，使有效信号居中、两端为合法插值；或对 scale<1 时先裁剪 warped 信号再对称填充；或限制 scale≥1。

### 🟠-2 DataLoader worker 随机种子对 ECGAugmentor 无效：多进程 fork 后各 worker 增强序列完全相同

- **位置**：`src/data_pipeline/dataset.py:406-413`（`_worker_init_fn` 只 seed `np.random`）；`src/data_pipeline/augmentor.py:86`（`self.rng = np.random.default_rng(random_seed)`）
- **问题描述**：`ECGAugmentor` 使用独立的 `default_rng`，而 `worker_init_fn` 只调 `np.random.seed(worker_seed)`，对 augmentor 的 rng 无影响。DataLoader 多进程 fork 时每个 worker 继承主进程同一 rng 状态 → 各 worker 的随机序列**逐位相同**。docstring 声称"为每个 worker 设置独立随机种子…保证增强的多样性和可复现性"（`:407-412`）不成立。
- **影响**：① 实际增强多样性等于单 worker（多进程无增益）；② 更换 `num_workers` 会改变样本↔增强的配对（分片边界变化），同一 seed 下不同 worker 数的运行结果不可复现对比；③ `train_backbone.py:130-137` 的对比学习 DataLoader 甚至未传 `worker_init_fn`。
- **建议修法**：在 `worker_init_fn` 中用 `torch.initial_seed()` 重新构造/重置 augmentor 的 rng（如 `augmentor.rng = np.random.default_rng(worker_seed)`），或让 augmentor 在每次调用时从 `np.random` 全局流取种子。

### 🟠-3 loader 吞掉全部异常返回 None，失败记录静默丢失且无逐条诊断

- **位置**：`src/data_pipeline/loader.py:283-285`
- **问题描述**：`load_record` 用 `except Exception` 全捕获后 `return None`，`iter_records`（`:362-365`）与 `preprocess_data_5k.py:252-255` 仅统计聚合 `skipped`，不记录是哪条记录、什么原因。损坏/缺 .mat 的记录会被静默跳过，导致 manifest 少于旧划分（正是 `repair_manifest_5k.py` 所修场景），且修复后仍有"无法加载则保持缺失"的静默路径（`repair_manifest_5k.py:82-84`）。
- **影响**：数据完整性核查只能事后靠 `verify_processed_5k.py` 对账；43K 级数据集上个别静默丢失难以察觉。
- **建议修法**：`load_record` 至少把 `record_ref` 与异常类别写入结构化日志/失败清单；`preprocess_data_5k` 结束时输出"旧划分应有 vs 实际写入"的逐源差异表。

### 🟠-4 manifest 无 labels 且无 label_extractor 时返回空标签张量 (0,)，批量时静默错位或崩溃

- **位置**：`src/data_pipeline/dataset.py:146-153`
- **问题描述**：`labels = np.array(record.get("labels", []), dtype=np.float32)` 在缺失时得到 shape (0,)；`:147` 的在线编码分支要求 `"dx_codes" in record and self.label_extractor` 同时成立。若两者任一不满足（如新增数据源的 manifest 只有 dx_codes、调用方未传 extractor），返回 shape (0,) 张量，DataLoader 默认 collate 直接抛错；若与其它样本混合则可能静默错位。
- **验证**：代码路径确认（构造无 labels 的 manifest 可复现空张量）。
- **建议修法**：无标签时显式抛 ValueError 并附 record_id，或统一在构造期校验 manifest 中 labels 长度==num_classes。

### 🟠-5 对比学习数据集无 manifest 时回退扫描全部 .npy，可重新引入 train+val+test 泄漏

- **位置**：`src/data_pipeline/dataset.py:202-208`
- **问题描述**：`ECGContrastiveDataset` 在 `{split}_manifest.json` 不存在时回退 `rglob("*.npy")` 全量扫描（含 val/test）。注释称"仅限无 manifest 的旧目录（NPU 环境 /cache）"，但 `train_simclr.py:92-95` 正是对 `/cache/data/processed` 用该数据集做对比预训练——若该目录缺 manifest，预训练将用到 val/test 信号（无监督预训练同样属信息泄漏红线）。代码只 warning 不拦截。
- **建议修法**：回退分支直接抛错（或要求显式 `allow_full_scan=True` 开关），杜绝静默泄漏。

## 🟡 可维护性/风格（部分含边界缺陷）

### 🟡-1 `_resample` 的"信号太短"守卫是死代码：更早的滤波步骤已崩溃

- **位置**：`src/data_pipeline/preprocessor.py:209-211`（守卫）；崩溃点在 `:176`/`:186`（`sosfiltfilt`）
- **验证**：对 (12,1) 信号调用 `ECGPreprocessor()(x, original_fs=257)` → `ValueError: The length of the input vector x must be greater than padlen, which is 27.`（来自 sosfiltfilt，根本没走到 `_resample`）。守卫 `:209` 永远无法按预期生效。正常路径中 loader 校验 ≥100 样本（`loader.py:261`）使其不可达，但守卫的鲁棒性承诺不实。
- **建议修法**：在 `__call__` 开头对 `ecg_signal.shape[1] < 28`（或 < 2·padlen）提前抛清晰错误；或删除该守卫。

### 🟡-2 `_normalize` minmax 分支把 vmax 记入 `per_lead_std`

- **位置**：`src/data_pipeline/preprocessor.py:330-331`
- **问题描述**：`means.append(float(vmin)); stds.append(float(vmax))`——minmax 下"std"槽位存的是 vmax，元数据语义错误（zscore 分支是正常的）。仅影响 return_meta 的元数据，不影响信号。

### 🟡-3 年龄归一化除以 120 但合法上限为 122，归一化年龄可 >1.0

- **位置**：`src/data_pipeline/metadata_parser.py:79-81`（`age / 120.0`）与 `:92`（上限 122）；`loader.py:100` 同样允许到 122
- **问题描述**：docstring（`:5`、`:79`）称"归一化到 [0,1]"，但 122 岁 → 1.0167。与 loader 的 `ECGSample.age`（≤122）逻辑重复，存在漂移风险。

### 🟡-4 形状校正的 (12,12) 歧义与 Agent 数据集无形状校验

- **位置**：`src/data_pipeline/dataset.py:119-125`（转置条件 `shape[1]==12 and shape[0]!=12`，`(12,12)` 既不被转置也不被拒绝）；`dataset.py:288-300`（`ECGDatasetForAgent` 只做转置、无 elif 校验，非 12 导联文件静默流入模型）

### 🟡-5 manifest 标签回填的 `[0]*27` 兜底（当前不可达，但属静默风险）

### 🟡-7 `verify_processed_5k.py` 硬编码期望 npy 数 43101

- **问题描述**：数据集增删（如 E09680 恢复、新增来源）会使校验误报 FAIL；应改为从旧 manifest 推导期望数。

### 🟡-11 `_find_record_path` 裸记录名搜索返回第一个 rglob 匹配，顺序未保证

- **位置**：`src/data_pipeline/loader.py:231-232`

## 💡 建议

### 💡-1 `ECGPreprocessor.segment()` 无任何调用方，且尾部静默丢弃
