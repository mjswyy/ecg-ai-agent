## 一、🔴 确认缺陷（已运行验证）

### 🔴-1 VQ-VAE perplexity 恒等于 1.0（公式错误）

**位置**：`src/context_modeling/ecg_tokenizer.py:54`

```python
perplexity = torch.exp(-torch.sum(F.one_hot(indices, self.codebook.num_embeddings).float() * torch.log(F.one_hot(indices, self.codebook.num_embeddings).float() + 1e-10)) / B)
```

**问题**：`one_hot * log(one_hot + 1e-10)` 逐元素恒为 0：
- 激活列：`1 * log(1 + 1e-10)`；在 float32 下 `1 + 1e-10 == 1.0`（尾数精度约 7 位十进制），`log(1.0) = 0`（已验证：float32 `1+1e-10 = 1.0`，log = 0）；
- 非激活列：`0 * log(1e-10) = 0`。

因此 `sum ≈ 0`，`perplexity = exp(-0/B) = 1`，与 codebook 使用情况完全无关。即便把公式"修对"（用经验频率 p_k），分母除以 `B` 也是错的——应对 `B*L`（全部 token 数）归一化。

**验证**：`VectorQuantizer(num_embeddings=16, embedding_dim=8)` 在随机输入上输出 perplexity 恒为 `1.0`；同时 codebook 实际使用 15/16 个码（与 ppl=1 矛盾，佐证公式失效）。

**影响**：perplexity 指标恒 1，无法用于监测 codebook 退化/使用率；训练日志与早停若依赖该指标会完全失真。

**修法**：按经验分布计算熵：`p = F.one_hot(indices, K).float().mean(dim=0)`（N=B*L 归一化），`ppl = exp(-(p * log(p + eps)).sum())`；或直接输出 `codebook 使用率 = (unique(indices).numel())/K`。

### 🔴-2 VQ-VAE 编解码长度不对称（解码器多一级上采样）

**位置**：`src/context_modeling/ecg_tokenizer.py:73-79`（编码器）与 `:87-93`（解码器）

编码器：`hidden_dims=(64,128,256)` 三级 stride-2 Conv1d（下采样 ×8）+ 1 个 stride-1 收尾卷积；
解码器：`rev_dims = list(reversed(hidden_dims)) + [input_channels]` = `[256,128,64,12]` **4 个元素**，循环内全部 `nn.ConvTranspose1d(..., 4, 2, 1)`（stride=2，上采样 ×16）。

**问题**：解码器比编码器多一个 stride-2 上采样级，`decode(indices)` 输出长度 = token 数 × 16，而输入信号只压缩了 ×8：

**验证**：`ECGTokenizer(input_length=4096)` 输入 4096 样本 → `encode` 得 512 tokens → `decode` 得 **8192** 样本（应为 4096）。`forward`（:104-106）通过 `recon[:, :, :x.shape[2]]` **截掉后半段**来掩盖长度错误——即每次重构都丢弃解码器输出的一半，重构目标与解码网格时间对齐错位 ×2。对不能被 8 整除的长度（如 4111 → 513 tokens → decode 8208），偏差更不规则。

**影响**：重构信号被"拉长后裁半"，重构质量与信息流不对称；`decode()` 接口（:96）返回长度与输入永远不匹配（除非恰好 0.5 倍）。

**修法**：解码器改为与编码器对称的 3 级 stride-2 + 1 级 stride-1 收尾（`ConvTranspose1d(..., 3, 1, 1)`），或删除一级上采样使总倍数 = 8。

## 二、🟠 疑似问题 / 潜在缺陷（特定输入或边界触发）

### 🟠-1 SupConLoss 实现并非论文标准 SupCon（分子用和而非逐正例求均值）

**位置**：`src/context_modeling/contrastive/losses.py:109-116`

```python
exp_sim = torch.exp(sim)
pos_sum = (exp_sim * pos_mask.float()).sum(dim=1)
neg_mask = (~pos_mask).fill_diagonal_(False)
neg_sum = (exp_sim * neg_mask.float()).sum(dim=1)
loss = -torch.log(pos_sum / (pos_sum + neg_sum + 1e-8))
```

论文（Khosla et al. 2020）标准形式：`L_i = -1/|P(i)| Σ_{p∈P(i)} log( exp(sim_ip) / Σ_{j≠i} exp(sim_ij) )`（对每个正例取 log 后求均值）；此处实现为 `-log( Σ_{p∈P(i)} exp(sim_ip) / Σ_{j≠i} exp(sim_ij) )`（先求和再取 log）。两者仅在 `|P(i)|=1` 时等价；`|P(i)|>1` 时梯度权重不同（标准版对每个正例等权，此实现对相似度高的正例权重更大，相当于正例内 softmax）。

**验证**（同一批 6 样本、每类 3 样本、temperature=0.07）：实现值 `5.0466` vs 标准值 `6.1369`，差值 1.09——目标函数与文档所称 "Supervised Contrastive Loss" 不一致，与文献 SupCon 结果不可直接对比。

**修法**：改为 `-log(exp_sim * pos_mask).sum(1)/pos_count - log(exp_sim.sum(1) + 1e-8)` 的标准形式，或至少在 docstring 中声明这是"和式变体"。

### 🟠-2 CLIP 训练对分割红线检查只警告不拦截（未来数据再生时的泄漏风险）

**位置**：`scripts/train_ecg_text_clip.py:111-112`

```python
if report_splits.get(rid, "unknown") != split:
    logger.warning(f"[红线] {rid} 报告 split={report_splits.get(rid)} != manifest {split}")
feats.append(i)   # 无论是否匹配都加入训练对
```

**问题**：报告自带 split 与 manifest split 不一致时仅打 warning，配对仍然加入。若数据重新生成（报告/清单不同步），跨 split 的文本（如 val 报告）会进入 CLIP 训练，直接违反脚本自称的"训练对只用 train 划分"红线，且静默发生。

**验证**：对**当前数据**逐对核对：train/val/test 三个划分的 split 失配数均为 **0**（10596/2247/2267 对全部一致），因此现数据无泄漏；但代码路径是软的。另外 ptb-xl 记录中缺报告的占比很高（train 15285 条中 4689 条无报告，被静默排除），覆盖情况值得关注。

**修法**：失配时 `continue` 排除该对，或 `raise`；至少把"失配即剔除"做成硬逻辑。

### 🟠-4 MetadataEncoder 对 NaN 年龄无防护，NaN 静默传播进特征与损失

**位置**：`src/context_modeling/metadata_encoder.py:71-73`


**验证**：`age=[[nan]]` → 输出特征含 NaN（`torch.isnan(out).any() == True`），且没有任何 NaN 检查，NaN 会一路传播到损失（静默）。同理 `sex` 为 NaN 时 `sex.long()` 得 `-2^63`（已验证），被 `clamp(0,2)` 静默当作 **0 = Female**（:80）——错误插补且无提示。

### 🟠-5 `train_multimodal.py` 的 `--no-text` 开关无效（ECG-only 消融实际不生效）

## 四、💡 建议与观测（非缺陷）

### 💡-1 CLIP 预训练对齐质量弱，且分类任务上未带来增益（可复现证据）

`outputs/clip_pretrained/meta.json`：`best_sum_r1 = 0.1967`（t2s 与 s2t 的 r1 之和，即单方向 r1 ≈ 0.1，2247 对）。`outputs/multimodal_fair/metrics.json`：B（CLIP 投影）test macro_auc 0.9129 **低于** A（原始特征）0.9192；D（CLIP+元数据）0.9436 仅微超 C（原始+元数据）0.9410。建议检查温度学习动态（logit_scale 是否顶到 clamp 边界）、batch 内负样本多样性（batch 256 vs 10596 对），或引入难负样本。

### 💡-2 元数据增益主要来自"数据集成员身份"（source one-hot）

`outputs/multimodal_fair/metrics.json`：C（含 source）0.9410 vs C2（仅临床，无 source）0.9048 —— source one-hot 贡献 +3.6 AUC，是典型的"知道记录来自哪个数据集"的捷径信号（脚本 docstring 已自述此质疑）。建议对外报告以 C2/D2 为准，或将 source 特征从"公平性主张"中剥离讨论。

### 💡-3 SupCon 数值稳定性：建议改用 logsumexp

**位置**：`losses.py:96,109-116`。`torch.exp(sim)` 在 temperature 极小（如 0.001）时 `exp(1000)=inf → NaN`；建议用 `logsumexp` 计算分母与分子，顺带消除 `1e-8` 魔法数。

### 💡-4 InfoNCE 末批尺寸波动

**位置**：`train_ecg_text_clip.py:139-145`。10596 % 256 = 100，末批 100 样本（负样本池显著变小）每次 epoch 损失噪声略大；可忽略或做 padding 处理。

### 💡-5 数据覆盖观测（非缺陷）

CLIP 训练对仅 10596 对（ptb-xl 且具报告），train 中 4689 条 ptb-xl 无报告被静默排除，cpsc/georgia/ptb/st_petersburg 数据集完全不参与 CLIP 对齐（`train_ecg_text_clip.py:106` 只保留 `ptb-xl_` 前缀）。若目标是跨数据集文本对齐，当前预训练只覆盖单一来源。
