## 发现清单

### 🟠-1 上传 WFDB 路径重命名为 "rec" 但未改写 .hea 内嵌信号文件名 → 上传功能对标准 PhysioNet 2020 记录必然解析失败

- **位置**：`web_demo/app.py:91-95`
  ```python
  stem = Path(td) / "rec"
  shutil.copy2(hea, stem.with_suffix(".hea"))   # → rec.hea
  shutil.copy2(mat, stem.with_suffix(".mat"))   # → rec.mat
  rec = wfdb.rdrecord(str(stem))                # 读 rec.hea
  ```
- **证据**：
  1. `wfdb.rdrecord` 读取信号数据用的是 **.hea 头部信号行内嵌的文件名**，而非传入的 record 名：`wfdb/io/record.py:2137` 调 `_rd_segment(file_name=record.file_name, ...)`，而 `record.file_name` 来自 `_header.py:1107` 对信号行的解析（`file_name` 是信号行第一个字段）。
  2. PhysioNet 2020 的 `.hea` 每个信号行形如 `A0001.mat 16+24 ...`，即内嵌 `A0001.mat`。重命名为 `rec.hea/rec.mat` 后，头部仍指向 `A0001.mat`，而临时目录里只有 `rec.mat` → `FileNotFoundError`。
  3. **实测复现**（temp 目录，未改仓库文件）：用 `wfdb.wrsamp` 生成合法记录 `orig.hea/orig.dat`，按 app 逻辑复制为 `rec.hea/rec.dat` 后，`wfdb.rdrecord('rec')` 报 `FileNotFoundError: .../orig.dat`；而 `wfdb.rdrecord('orig')` 正常。
  4. 对照：`scripts/analyze_ecg.py:183` 用 `wfdb.rdrecord(str(ecg_path.with_suffix("")))`（**原文件名，不重命名**）→ 正确。
- **修法**：在临时目录内**保留原文件名**复制两份文件（从 `.hea` 文件名推导原 stem），再 `wfdb.rdrecord(str(td / 原stem))`；或在复制后同步改写 `.hea` 头部信号行的文件名为 `rec.mat`。前者更简单且与"复制而非移动"的意图一致。
- **影响**：演示的"上传 WFDB 文件"核心功能对标准记录不可用。因异常被 `try/except` 兜底为"上传文件解析失败"提示，**不产生错误诊断**，故非红线，但功能已坏。

### 🟠-2 发现层只显示 top-5 阳性，而 LLM 白名单/知识库用全量 positives → 两个"发现层"阳性集合不一致

- **位置**：`web_demo/app.py:273-280`（显示用 top-5）vs `app.py:145,321`（LLM 白名单用全量 positives）vs `app.py:290`（知识库用全量 positives）
  ```python
  pos_rows = [f"- [阳性] {d['name']}: ..." for d in top_k if d.get("positive")]  # top_k 只有 5 条
  ...
  pos_names = {d["name"] for d in tools_out["classifier"].get("positives", [])}  # 全 27 类阈值判定
  ```
- **证据**：分类器 `predict`（`ecgfounder_classifier.py:140-148`）返回的 `positives` 是对全部 27 类做 Youden 阈值判定；`top_k` 仅 top-5。**实测 `smoke_demo.py`**：同一记录"确定性工具输出→发现层"只显示 3 个阳性（Pacing Rhythm / LAD / LBBB），而 LLM 双层报告"发现层"显示 6 个阳性（额外含 Atrial Flutter、Bradycardia、Supraventricular Premature Beats——这些是排名第 6 及以后、概率≥阈值的阳性）。两个"发现层"对同一份心电图给出不同阳性集合。
- **修法**：`app.py:275` 改迭代 `cls_out.get("positives", [])`（该列表已按阈值过滤），或明确截断并追加"另有 N 项阳性未展开"。
- **影响**：违反"发现层只显示阳性"的完整性预期——排名靠后但达 Youden 阈值的阳性在用户可见的发现层被**漏显示**（轻度低报），且与 LLM 报告口径不一致，削弱"发现层"作为锚定层的可信度。

### 🟡-3 HTML 转义不完整：3 条用户/LLM 可控文本未经 `html.escape` 直入 Gradio Markdown

- **位置**：
  1. `web_demo/app.py:302-303`：`report_md = f"⚠️ LLM 输出解析失败: {llm_out['parse_error']}"`，其中 `parse_error = raw[:200]`（`app.py:196`，LLM 原始输出）**未转义**。
  2. `web_demo/app.py:306-307`：`report_md = f"⚠️ LLM 调用失败...: {llm_out['error']}"`，`error = str(e)[:120]`（`app.py:192`）**未转义**。
  3. `web_demo/app.py:253`：`f"**输入**: {info}"`，上传路径 `info` 含 `rec.record_name`（`app.py:103`，来自用户上传的 `.hea`）**未转义**。
- **证据**：`app.py:335-338` 定义了 `esc = html.escape(..., quote=False)`，但只用于成功分支 `app.py:342-348`；上述 3 条失败/输入分支均未走 `esc`。三处文本都经 `gr.Markdown`（`app.py:405/407`）渲染。
- **修法**：对 `info`、`parse_error`、`error` 统一 `html.escape`（或抽一个 `md_esc` 辅助函数覆盖所有插值点）。
- **影响**：与项目自定的"LLM 文本 HTML 转义"医疗安全约定不一致。演示仅监听 `127.0.0.1`（`app.py:433`），实际危害有限；但解析失败分支直拼 LLM 原始输出是防御深度上的真实缺口。

### 🟡-4 `verify_r3_regression.py` "正常路径"断言太弱，测不出诊断/分类回归

- **位置**：`scripts/verify_r3_regression.py:42`
  ```python
  assert result.heart_rate is not None or result.diagnosis, "正常路径不应全失败"
  ```
- **证据**：脚本只 `register_ecg_tools(reg)`（R峰/QT，`verify_r3_regression.py:38`），**未注册分类器**。实测运行输出 `diagnosis=[]`（空）+ recommendations="诊断分类步骤未完成：分类器未返回有效诊断结果…"，断言靠 `heart_rate is not None`（92.9 bpm）短路通过。即使分类器/诊断工具整体回归到"永远失败"，该断言仍通过。docstring 声称"agent 正常路径不受影响"，但实际未验证诊断路径。
- **修法**：注册带真实权重的分类器工具，并把 `result.diagnosis`（非空）纳入断言；或至少断言 `result.diagnosis or result.recommendations` 中诊断相关字段非空。

### 🟡-5 `smoke_demo.py` 无 `--mock` 开关，key 存在时静默打真实付费 API

- **位置**：`scripts/smoke_demo.py:12-15`（整脚本无任何 mock/降级开关）

### 💡-6 `verify_*` 脚本在默认 Windows GBK 控制台下因 `✓` 字符抛 `UnicodeEncodeError` 崩溃

- **位置**：`scripts/verify_r3_safety.py:32`（同类的 `✓` print 还出现在 `:48,:55,:76,:78` 等）
- **证据**：首次运行 `python scripts/verify_r3_safety.py`（未设 `PYTHONUTF8`）在 `print("    ✓ ...")` 处 `UnicodeEncodeError: 'gbk' codec can't encode character '\u2713'`，进程 exit 1，断言未跑完。设 `PYTHONUTF8=1` 后才能跑通（且全部断言通过）。

### 💡-7 `RPeakDetector.last_result` 为共享可变状态（并发下良性竞争）
