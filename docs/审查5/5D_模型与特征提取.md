## 发现清单

### 🔴 5D-RED-1：R 峰已判“insufficient（噪声/导联脱落）”时，FeatureBank 仍用伪峰跑 QT，产出伪造 QT/QRS 值并解读为“shortened”

- **位置**：`src\ecg_models\feature_extraction\feature_bank.py` 第 89–99 行（QT 分析门控只判 `num_beats >= 2`，未判 `insufficient`）；根因联动 `r_peak_detector.py` 第 94–116 行（噪声守卫返回 20–30 个伪峰且 `insufficient=True`）。
- **证据（实测输出）**：
  ```
  # 0.03mV 低幅噪声（模拟导联脱落），R 峰层正确判 insufficient：
  num_beats: 30  insufficient: True  hr: 0.0
  # 但 FeatureBank 仍对 30 个伪峰执行 QT：
  feature heart_rate: 0.0  insufficient: True
  qt_ms: 139.0  qrs: 10.0  qt interp: shortened
  ```
  R 峰层已明确把整条信号判为“测量失败”，心率正确置 0 并带 `insufficient=True`；但 QT 层对同一批噪声伪峰产出 `qt_ms=139.0 ms`、`qrs_duration_ms=10.0 ms`（生理上 QRS 不可能 10ms），并给出临床解读 `shortened`。这是**纯噪声伪造出“QT 缩短”这一临床发现**，违反“失败显式化 / 不伪造数值”的医疗安全红线。
- **修法**：QT 门控改为 `if (not r_result.get("insufficient", False)) and r_result["num_beats"] >= 2:`；否则 `features.update(QTAnalyzer._empty_result())`。同时建议在 `FeatureBank.extract_all` 里把 `r_result["insufficient"]` 显式并入返回字典，避免下游仅凭 `heart_rate=0.0` 判断失败。

### 🟡 5D-YELLOW-1：`ECGAnomalyDetector.fit_threshold` 在 `device=None` 且模型在加速器上时输入张量不搬移 → 跨设备崩溃

- **位置**：`src\ecg_models\classifiers\anomaly_detector.py` 第 113–132 行。
- **证据（代码检查，本机无 GPU 故以推理为准）**：循环内 `if device: x = x.to(device)` —— 当调用方不传 `device`（文档示例即 `detector.fit_threshold(normal_loader)`）且模型位于 CUDA/NPU 时，`x` 保持 CPU，`self.anomaly_score(x)` 内 `self.backbone(x)` 以 CPU 张量喂 GPU 权重 → `RuntimeError`。而阈值 `dev = next(self.parameters()).device`（第 129 行）却是按模型设备创建，二者口径不一致——阈值“以为”在加速器上，输入“还在”CPU。CPU 模型下 `device=None` 可正常工作（实测阈值 0.077、`threshold` 仍为注册缓冲、进入 `state_dict`），故为加速器专属潜伏缺陷。
- **修法**：`dev = device if device is not None else next(self.parameters()).device`，并统一 `x = x.to(dev)`；阈值按 `dev` 创建。

### 🟡 5D-YELLOW-2：HRV 频域对“恒定 RR（如起搏心律）”返回 `lf_hf_ratio=0.0 / total_power=0.0`，无 `insufficient` 标记

- **位置**：`src\ecg_models\feature_extraction\hrv_analyzer.py` 第 134–145 行。
- **证据（实测）**：`HRVAnalyzer()._frequency_domain(1000*np.ones(50))` → `{'lf_power': 0.0, 'hf_power': 0.0, 'lf_hf_ratio': 0.0, 'total_power': 0.0}`，**无 `insufficient` 键**。恒定 RR（起搏/完全规则）时去趋势后为 0，PSD 全 0，LF/HF 实为 0/0 未定义量，却被 `hf_power > 1e-10` 守卫落成字面 `0.0`，且不进入第 104–106 / 130–132 行的 `insufficient` 返回分支。下游可能把 `LF/HF=0.0` 当真实临床值呈现。
- **修法**：`total_power` 低于阈值（如 < 1e-8）时返回 `{lf_power: None, hf_power: None, lf_hf_ratio: None, total_power: None, insufficient: True}`，与数据不足分支口径一致。

### 🟡 5D-YELLOW-3：`ECGTrainer.evaluate` 全正类守卫存了 0.5 阈值却从不写 `preds_optimal[:, c]`，全正类 F1 恒为 0，低估 macro_f1 / Challenge Score

- **位置**：`src\ecg_models\trainer.py` 第 478–499 行（全正分支第 482–487 行 `continue` 跳过第 498 行的 `preds_optimal[:, c]` 赋值）。
- **证据（实测，4 类 8 样本，class2 全正）**：
  ```
  val_thresholds: [0.49907333 0.5 0.5 0.49955663]
  # class2 阈值 0.5，但 preds_optimal 列保持 0：
  f1 col2 if preds all-zero: 0.0
  f1 col2 if preds = probs>=thresh: 0.7692307692307693
  macro_f1 reported: 0.3611111111111111   # 被全正类拖低
  ```
  全正类阈值按 0.5 写入检查点（测试集评估时 `thresholds` 分支会正确套用 0.5），但拟合当轮的 `preds_optimal` 列停在 `np.zeros_like`，使该类的 macro_f1 与 Challenge Score 的 Fβ 项被低估（口径与保存的阈值自相矛盾）。
- **修法**：全正分支补 `preds_optimal[:, c] = (probs[:, c] >= 0.5).astype(np.float32)`（与保存阈值一致）；全负分支同理显式置 0（当前默认即 0，但显式更稳）。

### 🟡 5D-YELLOW-4：QTAnalyzer 心率兜底伪造 60 bpm + 不可达死分支

- **位置**：`src\ecg_models\feature_extraction\qt_analyzer.py` 第 109–114 行。
- **证据（代码检查）**：`hr = 60000.0 / rr_ms if rr_ms > 0 else 60.0`（第 112 行）——当 `rr_ms <= 0`（`r_peaks` 传入含重复/非升序索引时 `np.median(np.diff(...))` 可为 0）会伪造 `60.0`；`else: rr_ms, hr = 1000.0, 60.0`（第 114 行）为死代码（`analyze` 已在第 53 行 `len(r_peaks) < 2` 时提前返回，`_compute_results` 恒在 `len>=2` 下进入）。这是与“严禁伪造固定值”同一反模式的心率兜底。
- **修法**：`rr_ms <= 0` 时返回 `_empty_result()`（或 `heart_rate: None`），删除第 114 行死分支。

### 💡 5D-HINT-1：样本熵 `A==0` 时返回 0.0，方向相反（应“高度不规则”而非“完全规则”）

- **位置**：`src\ecg_models\feature_extraction\hrv_analyzer.py` 第 195–198 行。
- **证据（代码检查，简单构造难以稳定命中）**：`return max(0.0, -np.log(A / B)) if A > 0 else 0.0` —— 当 `B>0`（长度 m 有匹配）而 `A==0`（长度 m+1 无匹配）时，按定义 SampEn 应为高熵/无穷（数据在下一尺度完全无重复），却被报成 `0.0`（含义为“完全规则”）。`B==0` 已按 None 处理，`A==0` 遗漏。
- **修法**：`A==0` 时返回 `None`（并置 insufficient）或 `+inf`，与 `B==0` 语义对齐。

### 💡 5D-HINT-2：`np.trapz` 已弃用（numpy 2.x DeprecationWarning，3.0 将移除）

- **位置**：`src\ecg_models\feature_extraction\hrv_analyzer.py` 第 137–141 行（3 处 `np.trapz`）。
- **证据（实测）**：`DeprecationWarning: `trapz` is deprecated. Use `trapezoid` instead...`。
- **修法**：改用 `np.trapezoid`（或 `scipy.integrate.trapezoid`）。

### 💡 5D-HINT-3：`ECGAnomalyDetector.fit_threshold` 空 loader 崩溃

- **位置**：`src\ecg_models\classifiers\anomaly_detector.py` 第 128–131 行。
- **证据（实测）**：空 DataLoader → `ValueError: need at least one array to concatenate`。
- **修法**：`scores` 为空时告警并返回（不设阈值 / 保持 `_fitted=False`）。

### 💡 5D-HINT-4：`PositionalEncoding` 对奇数 `d_model` 的 sin/cos 切片广播会失配

- **位置**：`src\ecg_models\backbone\transformer_encoder.py` 第 49–50 行。
- **证据（代码检查）**：`div_term` 长度为 `ceil(d_model/2)`；奇数 `d_model` 时 `pe[:, 1::2]`（`floor(d_model/2)` 列）与 `cos(position*div_term)`（`ceil(d_model/2)` 列）形状不一致，`__init__` 即抛错。当前 `d_model=256`、`nhead=8` 且 `assert d_model % nhead == 0`，恒为偶数故不触发；属潜在约束。
- **修法**：`div_term` 生成用 `arange(0, d_model//2 * 2, 2)` 并让 sin/cos 各取 `d_model//2`，或显式断言 `d_model % 2 == 0`。

### 💡 5D-HINT-5：FeatureBank 失败键口径不统一（HRV `insufficient` vs QT `error`）

- **位置**：`src\ecg_models\feature_extraction\feature_bank.py` 第 84–99 行（合并两处 empty 结果）；`hrv_analyzer._empty_result`（`insufficient: True`）vs `qt_analyzer._empty_result`（`error: "insufficient_data"`）。
- **证据（代码检查）**：失败时返回字典同时含 `insufficient: True` 与 `error: "insufficient_data"` 两种键，消费方需各自兼容。
- **修法**：统一为单一失败键（如统一 `insufficient: True`），或至少在 `FeatureBank` 层规整。

## 阳性结论

1. **加载安全（加载安全维度）**：`safe_torch_load` 默认 `weights_only=True` + numpy 白名单（`numpy.core.multiarray.scalar` / `numpy._core.multiarray.scalar` / `_reconstruct` 双名映射），失败时不再静默回退完整 pickle；`ECGTrainer.load_checkpoint` 走该封装并支持 `key_prefix` 剥离与 `strict`。实测 torch 2.7.1 下加载正常。
2. **阈值来源与口径（阈值来源维度）**：`train_multilabel` 早停时同步快照 best 权重与 best 时刻 `val_thresholds`，训练结束后回填二者，保证“报告指标权重 == best_model.pt 权重 == 阈值口径”；`_save_checkpoint`/`load_checkpoint` 随检查点保存/加载 `val_thresholds`；`evaluate` 用 Youden `J=TPR−FPR` 判据，全负/全正类与非有限阈值兜底 0.5，且禁止在测试集现算阈值（外部评估必须传验证集阈值）。
3. **失败显式化（医疗安全维度）**：`RPeakDetector` 对 <2 峰、RR 全部生理过滤失败、以及 QRS 频段（5–15Hz 带通峰峰值 <0.15mV 的噪声/导联脱落）三类情况均显式返回 `insufficient=True` 与 `rhythm="insufficient_data"`，不再把检不出心跳伪装成确定性节律（实测噪声输入正确判 insufficient）。
4. **不伪造数值（医疗安全维度）**：HRV 数据不足返回 `None`+`insufficient`（与 QT `None` 口径一致）；QT `_simple_delineate` 已停用（`raise RuntimeError`），不再产出与信号无关的固定窗口常量；`_safe_wave_index` 对 `np.float64`/`np.floating` 的 NaN/Inf 守卫覆盖 numpy 标量。QT 失败（非 ImportError 异常亦）统一显式失败。
5. **数值边界（数值边界维度）**：ASL 负类聚焦用 `max(p−m,0)^γ`、log 参数 clamp 到 `[eps,1−eps]`、logits clamp `[−50,50]`，实测极端 logits 无 NaN（`AsymmetricLoss` 对随机 logits 输出 0.403，>0）；`_info_nce_loss` 负样本掩码同时剔除自身与正样本对；训练/评估对 loss 与梯度做 NaN/Inf 守卫；`evaluate` 对 logits 做 `np.nan_to_num`。
6. **骨干接口一致性（模型维度）**：ResNet1D / xResNet1D101 / InceptionTime / ECGTransformer / Net1D 均提供 `feature_dim`，`ArrhythmiaClassifier`、`ECGAnomalyDetector`、`ecg_text_clip` 均按 `backbone.feature_dim` 取维度；`tests\test_ecg_models.py` 实测 4 个骨干输出维度与 `feature_dim` 一致（512/512/128/256），全部通过。
7. **ECGFounder 冻结特征链路**：`Net1D.feature_dim = filter_list[-1] = 1024` 与 `ecgfounder_classifier` 的 MLP 头 `Linear(1024, 512)` 一致，`dense=Identity()` 取特征后 `forward` 返回 `deep_features`（`out.mean(-1)`）维度正确。
8. **超长序列显式失败**：`ECGTransformer.PositionalEncoding.forward` 对超过 `max_len` 的序列 `raise ValueError`（fail-loud），不再因广播失败而崩溃。
