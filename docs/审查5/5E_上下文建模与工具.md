## 发现清单

### 🟠 1. `detect_device` 不校验显式多卡索引 "cuda:N"/"npu:N"，"越界告警回退"只在 `get_device_object` 生效，活跃训练脚本实际绕过该保护

- 位置：`src/utils/device_utils.py` `detect_device()`（第 49–67 行），尤其第 60–67 行仅对裸 `"npu"`/`"cuda"` 做可用性校验，第 67 行 `return device_str` 对 `"cuda:N"`/`"npu:N"` 原样返回。
- 证据（CPU-only 机器实测）：
  ```
  'cuda'   -> detect: 'cpu'      （裸 cuda 正确回退）
  'cuda:0' -> detect: 'cuda:0'   （无回退，即使本机无 CUDA）
  'cuda:99'-> detect: 'cuda:99'  （越界索引，无告警、无回退）
  'npu:0'  -> detect: 'npu:0'    （无 torch_npu，无告警、无回退）
  get_device_object('cuda:99') -> device(type='cpu')  （此路径有告警回退）
  ```
  交叉核对（范围外脚本，仅佐证）：`scripts/train_ecg_text_clip.py:83`、`scripts/train_ecgfounder_head.py:228` 均为 `device = torch.device(detect_device(args.device))`——直接用 `detect_device` 而非 `get_device_object`，因此对显式多卡索引，"越界告警回退 CPU"（项目背景声明的 device_utils 特性）实际被绕过，最终在 `.to("cuda:99")` 时以 CUDA 运行时错误暴露，而非干净告警回退。
- 影响：用户在无 CUDA / 卡数不足的机器上 `--device cuda:N`（N 越界）时，得不到声明的"告警回退"，得到的是延迟的 CUDA out-of-range 崩溃；且 `"cuda:N"` 连 `is_available()` 检查都跳过（裸 `"cuda"` 反而会检查）。
- 修法：让 `detect_device` 复用 `get_device_object` 的索引解析/范围/可用性校验逻辑（或直接在 `detect_device` 内对 `"cuda:N"`/`"npu:N"` 解析并校验，越界/不可用时告警并返回 `"cpu"`），保证两条入口行为一致。

### 🟡 2. `InfoNCELoss` 缺 temperature<=0 守卫：负温度静默产出 NaN，零温度在构造期崩溃

- 位置：`src/context_modeling/contrastive/losses.py` `InfoNCELoss.__init__`（第 23–26 行）。`logit_scale = torch.log(torch.tensor(1.0 / temperature))` 无入参校验；同类 `SupConLoss` 已加守卫（第 81–82 行），此处未同步。
- 证据（实测）：
  ```
  InfoNCELoss(temperature=-1.0) -> init ok, logit_scale=nan
      forward 输出 nan，torch.isnan(out)=True   （clamp 无法修复 NaN）
  InfoNCELoss(temperature=0.0)  -> ZeroDivisionError: float division by zero
      （Python 浮点 1.0/0.0 在 __init__ 直接抛异常）
  ```
  对比：`SupConLoss(temperature=0)` 正确抛 `ValueError`（实测通过）。
- 影响：默认 0.07 下稳定，但任何调用方误传 0 会得到难定位的 `ZeroDivisionError`；误传负值会静默训练出 NaN 梯度（clamp 对 NaN 无效），定位困难。属数值稳定性维度缺陷。
- 修法：`__init__` 开头加 `if temperature <= 0: raise ValueError(f"InfoNCELoss temperature 必须 > 0，收到 {temperature}")`，与 `SupConLoss` 一致。

### 🟡 3. `safe_load.register_safe_globals` 的日志与行为不符："回退 weights_only=False" 从未发生

- 位置：`src/utils/safe_load.py` 第 78–81 行。`add_safe_globals` 不可用（旧 torch）时 `logger.warning("...回退 weights_only=False")`，但 `safe_torch_load` 中 `weights_only` 参数仍为 True，实际从不回退。
- 证据：代码阅读（第 95–104 行 `safe_torch_load` 无任何依据该日志改变 `weights_only` 的分支）。当前 torch 2.7.1 具备 `add_safe_globals`，该分支不可达，但日志文案一旦触达即为事实性错误。
- 影响：仅日志误导（行为上更安全——仍保持 `weights_only=True`）；但会让开发者误以为存在"安全加载失败即回退不安全加载"的路径，或在旧 torch 上报错时困惑于"已回退却仍失败"。
- 修法：把日志改为准确描述，例如"add_safe_globals 不可用；保持 weights_only=True（numpy 白名单无法注册，含 numpy 对象的检查点将加载失败）"。

### 💡 4. `TextEncoder` max 池化用 0 掩 padding：全负 hidden 时被 padding 的 0 污染

- 位置：`src/context_modeling/text_encoder.py` 第 97 行 `pooling == "max"` 分支。
- 证据（实测，模拟 line 97 计算）：
  ```
  hidden=[[[-5.0,-5.0],[0.0,0.0]]]（token0 真实值 -5，token1 为 PAD），mask=[[1,0]]
  (hidden*mask).max(1)  -> [[0.0, 0.0]]          （错误：0 压过 -5）
  hidden.masked_fill(mask==0,-1e9).max(1) -> [[-5.0,-5.0]]（正确）
  ```
- 影响：仅 `max` 池化路径；现役链路（`extract_text_embeddings.py` / 公平版脚本）只用 `mean`，故缺陷不可达。若恢复 max 池化，全负 hidden（某些激活函数下常见）会取到 padding 的 0 而非真实最大值。
- 修法：改为 `outputs.last_hidden_state.masked_fill(attention_mask.unsqueeze(-1)==0, -1e9).max(1).values`。

### 💡 5. `TextEncoder` 占位编码器硬编码 768 维且返回张量无 device

- 位置：`src/context_modeling/text_encoder.py` 第 49 行 `self._output_dim = 768` 与第 102–105 行 `_placeholder_encode`。
- 证据（实测，构造 encoder=None 的占位对象）：
  ```
  placeholder shape/dev/dtype = torch.Size([2, 768]) cpu torch.float32   （无 device、无 dtype 对齐）
  ```
- 影响：仅当 transformers 缺失/模型加载失败时触发（现役均加载真实 transformers + `mean`，未触发）。若下游将占位输出与 GPU 上的 ECG 特征拼接，会因 device 不一致报错；`768` 对非 BERT-base 模型也不正确。
- 修法：占位输出跟随模型/输入 device（`torch.zeros(..., device=self.encoder.device if self.encoder is not None else None)` 或统一 `self._output_dim` 与真实 `hidden_size`），并将 `_output_dim` 由加载结果回填而非硬编码。

### 💡 6. `device_utils` 的 CPU 纯 FP32 回退分支在现代 torch 上实际不可达

- 位置：`src/context_modeling/../utils/device_utils.py` `_init_amp` 第 163–180 行。
- 证据（CPU-only 机器实测）：
  ```
  GradScaler type = <class 'torch.amp.grad_scaler.GradScaler'>     （真实类，非 _DummyGradScaler）
  autocast    type = <class 'torch.cuda.amp.autocast_mode.autocast'>（真实类，非 _DummyAutocast）
  ```
- 影响：`torch.cuda.amp` 在 CPU-only 的 torch 构建下也能导入，故第 177–180 行的 `_DummyGradScaler/_DummyAutocast` 及 `logger.warning("AMP 不可用…纯 FP32")` 永不触发。CPU 上 `autocast` 仍是真实 CUDA autocast，安全性完全依赖调用方传 `enabled=(device != "cpu")`；若误传 `enabled=True` 会在 CPU 上走 CUDA 路径失败。
- 修法：在 CPU-only（无 NPU/CUDA）时显式把 `GradScaler/autocast` 指向 dummy 类（而非仅当 import 失败），使"纯 FP32"分支名副其实，并对 `enabled=True` 也安全。

## 阳性结论

1. **离线模块护栏全部有效**：7 个已下线模块（`ecg_text_clip`、`ecg_tokenizer`、`metadata_encoder`、`multimodal_model`、`fusion/cross_attention`、`fusion/gated_fusion`、`fusion/late_fusion`）实测 `import` 均抛 `RuntimeError`；`raise` 位于模块顶部、imports 之前，无法绕过。
2. **包级护栏边界正确**：`src.context_modeling.fusion`、`src.context_modeling.contrastive` 两个包 `__init__.py` 本身可导入（仅 docstring），但 `from src.context_modeling.fusion import cross_attention` 实测抛 `RuntimeError`；活跃的 `contrastive.losses` 可正常导入（`train_ecg_text_clip.py` 正在使用），护栏未误伤现役链路。
3. **安全加载无静默回退**：`safe_torch_load` 默认 `weights_only=True` + numpy 白名单；实测含 `np.float64`/`np.ndarray`/`np.dtype` 的检查点对象可成功 `weights_only=True` 加载（`_NumpyScalarShim` 转发到 `numpy._core.multiarray.scalar` 生效）；对不可信自定义对象，`fallback=False` 实测抛带说明的 `RuntimeError` 而非静默降级，安全红线守住。
4. **InfoNCE 温度数值稳定**：`logit_scale` 前向先 clamp 到 `[ln(1/100), ln(100)]` 再 exp，等效温度稳定在 `[0.01, 100]`；实测 `logit_scale=1000` 时温度钳至 0.01、`logit_scale=-1000` 时钳至 100，无漂移/溢出。
5. **SupConLoss 边界处理正确**：`temperature<=0` 抛 `ValueError`（实测）；空正样本（batch=1）实测返回 0.0 标量（保留计算图），不再产出 NaN；负样本掩码已同时剔除自身（第 117 行），避免对角项主导分母。
6. **多卡回退逻辑（`get_device_object` 路径）正确**：`cuda:99`、`npu:99`、`cuda:abc`、`cuda:-1` 等非法/越界索引实测均告警并回退 `cpu`（含 NPU 越界的同类校验，非仅 CUDA）。
7. **范围内无测试集泄漏路径**：活跃模块 `text_encoder.py`（文本编码）、`losses.py`（对比损失）均不处理 train/val/test 划分；历史"文本进入推理"的泄漏路径（`multimodal_model.forward` 将 text_feat 送进 fusion→classifier）已随模块下线（import 即 raise），不可达。公平版（`train_multimodal_fair.py`/`train_ecg_text_clip.py`）文本仅作监督。
8. **torchvision_stub 失败即抛**：stub 的 `decode_image`/`pil_to_tensor` 等图像函数实测为 `_fail`（调用即抛 `RuntimeError`），不会静默产出错误图像结果；纯文本任务（`extract_text_embeddings.py` 导入顺序正确）不受影响。

（注：🔴 级发现为 0。范围内未发现数据泄漏、pickle 任意代码执行、维度对齐崩溃、温度 NaN 漂移等致命问题；现役链路的已知数值/加载/多卡边界处理均已正确。）
