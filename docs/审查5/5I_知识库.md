## 发现清单

### 🔴-1 distill `--verify` 模式必然崩溃（VERIFY_PROMPT 花括号未转义）

- 位置：`scripts/distill_knowledge.py` L64-72（`VERIFY_PROMPT` 模板）、L200-210（`.format()` 调用与 try 边界）。
- 证据：`VERIFY_PROMPT` 末尾为 `Answer JSON: {"faithful": true/false, "issues": ["..."]}`，其中 `{` 是字面花括号但未转义。`str.format(source=..., entry=...)` 会把 `{"faithful"` 当作替换字段名解析。实测（load 模块后调用）：
  ```
  FORMAT RAISED: KeyError '"faithful"'
  ```
  且 `.format()` 调用在 L201，位于 try/except（L203-209 仅包住 `_chat`/`json.loads`）之外，异常会向上冒泡出 `distill_one`，而 `main()` L241 无外层兜底，导致整个批次提炼崩溃。旁证：`data/knowledge/distilled/*.jsonl` 中 `_verified` 字段计数为 0（`--verify` 从未成功产出过）。
- 影响：`--verify`（提炼保真度校验）这一文档化功能完全不可用，且一旦开启会中断整个蒸馏批处理，而非优雅降级。
- 修法：把 `VERIFY_PROMPT` 中的字面花括号转义为 `{{`/`}}`（或改用 `%`/拼接），并将 L201 的 `.format()` 移入 try 块，使校验失败仅置 `_verified=False` 而不中断批次。

### 🟠-1 distill 内容级缓存 append 不幂等 + compile 不去重（陈旧条目残留风险）

- 位置：`scripts/distill_knowledge.py` L163-169（`is_done`/`put`）、`scripts/compile_knowledge.py` L362-363（按行读入全部条目，无 doc_id 去重）。
- 证据：`DistillCache.put` 以 `open(self.path, "a")` 追加写。内容级缓存使"重抓同一 doc_id 但内容更新"时 `is_done` 变 False 并重新蒸馏、`put` 追加新行——但**旧行（旧 text_hash）不会被删除**。`compile_knowledge` 随后把同一 jsonl 的所有行都读入 `entries`，无按 doc_id 去重。于是同一 doc_id 的陈旧 + 新鲜两份条目并存：`n_sources` 被重复计数、`sources` 清单出现重复 doc_id、且若陈旧文本与新鲜文本规范化后不同，`join_list` 会将其当作两条独立文本同时注入 KB（陈旧医学内容漏进 LLM 上下文）。当前数据经 `backfill_distill_text_hash.py` 一次性去重后干净（实测各 distilled 无重复 doc_id），属**潜伏缺陷**，一旦重抓重蒸馏即复发。
- 影响：缓存失效后知识库内陈旧内容与新鲜内容并存，违背"内容级缓存"预期，影响医学结论可信度。
- 修法：`put` 改为重写整文件并按 doc_id 去重（保留最新），或在 `compile_knowledge` 读入时按 doc_id 去重取最后一行；二选一即可，建议两端都加防。

### 🟡-1 内容缓存键只哈希 `text`，title/url 修正不失效缓存

- 位置：`scripts/distill_knowledge.py` L141-145（`doc_key` 仅 `json.dumps(doc.get("text",""))`）、L163-165（`is_done`）。
- 证据：`doc_key` 只对 `text` 取 SHA256。蒸馏记录还携带 `title`/`url`（L250、L247），这些字段可独立于 `text` 变化。实测 `raw/prolonged_qt_interval/litfl_long-qt-syndrome.json` 的 `title` 为 `"Prolonged QT Interval"`（类名，非真实页标题），而对应 `distilled` 行 `title: None`、`text_hash` 与 raw 完全一致（`444541eab334ff93` MATCH）——说明 raw 曾重抓改了 title 但 text 未变，缓存判定"已完成"，蒸馏记录中的 title 陈旧未更新，最终 compile 靠 `condition` 回退才凑出正确标题。
- 影响：3E-Y7 的"title 透传"修复在 title 变化而 text 不变时无法生效，引用标题可能长期陈旧/为空。
- 修法：`doc_key` 把 `title`、`url`（必要时 source/grade）一并纳入哈希；或 `is_done` 除 text_hash 外再比对 title/url。

### 🟡-2 "Prolonged QT Interval" 类定义被 LQTS 综合征定义污染

- 位置：`scripts/compile_knowledge.py` L141-147（`_condition_matches`）、L149-167（`_text_matches`）、L246-259（`_definition`）；数据 `classes.json` → `Prolonged QT Interval`。
- 证据：该类的 LITFL 来源是陈旧 raw `litfl_long-qt-syndrome.json`（URL `https://litfl.com/long-qt-syndrome/`，3E-Y8 之前"long-qt-syndrome"尚为主页名），其编译定义与 `definition_source` 为：
  ```
  definition: "Long QT Syndrome (LQTS) produces prolonged ventricular repolarisation, which predisposes to malignant ventricular arrhythmias."
  definition_source: {source: litfl, grade: C, url: .../long-qt-syndrome/}
  ```
  即"QT 间期延长"这一 ECG 测量发现类，其定义被写成了遗传综合征 LQTS 的定义。根因二：① 陈旧 LQTS 兜底页数据（qt-interval 专页未抓成）；② 相关性格关对 `Prolonged QT Interval` 的类名关键词只剩 `["qt"]`（`prolonged`/`interval` 均被 `CLASS_STOPWORDS` 停用），`\bqt\b` 对 "long QT syndrome" 也命中，无法区分"QT 间期"与"LQTS 综合征"。
- 影响：知识条目注入 LLM 上下文后，把"QT 间期延长"（测量）与"LQTS 综合征"（疾病）混为一谈，医学结论口径不精确。
- 修法：重抓该类的 `qt-interval` 专页并删除陈旧 `litfl_long-qt-syndrome.json`；给 "prolonged qt interval" 类补充 "interval/measurement" 语义或对 LQTS 词（`syndrome`/`lqts`）做负向排除。

### 🟡-3 LITFL 来源 doc_id/title 与实际 URL 不一致（引用完整性）

- 位置：`scripts/crawl_knowledge.py` L302-312（候选 slug 构建）、L337-344（`doc_id = f"litfl_{slug}"` 用首个 slug，`url` 用候选串）。

### 🟡-5 标准缩写 "LAFB" 无法解析（返回 None）
