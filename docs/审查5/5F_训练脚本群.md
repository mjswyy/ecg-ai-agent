### 🟠-1 train_multimodal_fair.py：`safe_torch_load` 的 import 先于 `sys.path` 注入，脚本按文档方式运行即崩

- **位置**：`scripts/train_multimodal_fair.py:17`（`from src.utils.safe_load import safe_torch_load`）对比 `:28`（`sys.path.insert(0, str(Path(__file__).parent.parent))`）。
- **证据**：
  - 本仓库无 `setup.py`/`pyproject.toml`，`src` 仅靠脚本内的 `sys.path.insert(0, 仓库根)` 才能被 import。`python scripts/xxx.py` 运行时 `sys.path[0]` 是 `scripts/` 目录，**不含仓库根**（Python 3 对脚本执行不自动加 CWD）。
  - 实证：令 `sys.path[0] = ...\ecg-ai-agent\scripts`（仓库根移除）时 `importlib.util.find_spec('src') == None`，即第 17 行的 `from src.utils.safe_load ...` 抛 `ModuleNotFoundError: No module named 'src'`。
  - `paper/main.md:200` 文档化调用正是 `python scripts/train_multimodal_fair.py`。同仓其它活跃脚本（`train_ecgfounder_head.py:27-28`、`train_ecg_text_clip.py:29-30`、`train_backbone.py:24-26`、`train_simclr.py:17-20`）均把 `sys.path.insert` 放在 `src` import 之前，唯独本脚本（及两个 DEPRECATED 脚本）顺序相反。
- **修法**：把第 17 行 `from src.utils.safe_load import safe_torch_load` 移到第 28 行 `sys.path.insert(...)` 之后（或改用 `src.utils.device_utils` 等同样延迟 import 的写法）。

### 🟡-2 train_ecgfounder_head.py：`youden_thresholds` 缺非有限阈值守卫，AUC≤0.5 的类会取到 `inf` 阈值

- **位置**：`scripts/train_ecgfounder_head.py:71-82`（本地 `youden_thresholds`，`:81` `ths[c] = float(t[np.argmax(j)])`）；`src/evaluation/metrics/classification.py:48-59` 的 canonical 版本同样缺守卫。
- **证据**：
  - sklearn 1.9.0 的 `roc_curve` 恒返回 `thresh[0] = inf`（已实证）。当某类验证集 AUC≤0.5 时，`j = tpr - fpr` 全程 ≤0，`np.argmax(j) == 0` → 取到 `t[0] = inf`（已实证：反相关得分样本得 `threshold=inf`）。
  - `inf` 阈值写入后，测试集 `probs >= inf` 恒为 False → 该类恒判负、`macro_f1_youden` 该类 F1=0。
  - 对比：`src/ecg_models/trainer.py:495-496` 已对同一问题加了 `if not np.isfinite(best_thresh): best_thresh = 0.5` 守卫（并注释了 sklearn 1.9 的 inf 行为），而主结果脚本与 canonical `classification.py` 的两份并行实现**未同步**该守卫，口径不一致。
  - 该函数被主结果脚本 `train_ecgfounder_head.py:244`（`ths = youden_thresholds(y_val, val_probs)`）用于确定测试阈值，属于现役数字链路。
- **修法**：在 `youden_thresholds` 两处实现中，`argmax` 取阈值后加 `if not np.isfinite(v): v = 0.5`（与 `trainer.py` 口径一致）。

### 💡-2 train_multimodal_fair.py：训练/评估全程 CPU，不自动加速

- **位置**：`scripts/train_multimodal_fair.py:83-128`（`train_head`）、`:131-141`（`run_variant`）。
- **证据**：`train_head`/`run_variant` 无任何 `--device` 参数、无 `.to(device)`，`Head` 模型与特征张量全部留在 CPU；与 `train_ecgfounder_head.py:228`、`train_ecg_text_clip.py:83`、`train_backbone.py:70` 均接入 `detect_device` 的做法不一致。MLP 规模小（1024→512→27）CPU 可跑，但 6 变体 × 50 epoch 纯 CPU 明显偏慢。
- **修法**：可选为 `train_head` 增加 `device` 参数并 `.to(device)`（功能正确性不受影响，仅效率）。

### 💡-3 train_ecgfounder_head.py：线性探针只跳过全负类，未跳过全正类

- **位置**：`scripts/train_ecgfounder_head.py:258-264`。
- **证据**：`if y_train[:, c].sum() == 0: continue` 只防"训练集全负"，未防"训练集全正"（`sum() == len(y_train)`）。若某类训练集全正，`LogisticRegression(solver="lbfgs")` 对单类目标抛 `ValueError: This solver needs samples of at least 2 classes`，导致 `--with-linear-probe` 整个崩溃。同类守卫在 `youden_thresholds`（`:77`）、`evaluate` 的 mAP（`:111-113`）与 `trainer.evaluate`（`:482-487`）里都是 `0 < sum < len` 双端条件，此处口径不一致。另：`clf.fit(x_train, ...)` 用未标准化的原始 1024 维特征（下界参考可接受）。
- **修法**：把条件改为 `if y_train[:, c].sum() == 0 or y_train[:, c].sum() == len(y_train): continue`。

### 💡-4 GPU 可复现性：活跃脚本只设 CPU 种子，未设 CUDA 种子

- **位置**：`train_ecgfounder_head.py:146-147`、`train_ecg_text_clip.py:86-87`、`train_multimodal_fair.py:85-86`（以及 `train_backbone.py:85-91`、`train_simclr.py:61-67`）。
- **证据**：均调用 `torch.manual_seed` / `np.random.seed`（/ `random.seed`），但未调用 `torch.cuda.manual_seed_all`、未设 `torch.backends.cudnn.deterministic`。在 GPU 上 cuDNN 卷积/注意力存在非确定性，严格复现仍可能有微小波动；主结果脚本声称"保证可复现"但实际只保证了 CPU 侧。
- **修法**：在 `device` 确定后补 `torch.cuda.manual_seed_all(seed)`（可选 `torch.backends.cudnn.deterministic=True`）。

### 🟡-3 train_modelarts.py（DEPRECATED）：输出同步路径硬编码，与训练写入目录可能不一致

- **位置**：`scripts/train_modelarts.py:198-211`（`sync_output_to_obs` 的 `local_dir = "/cache/output"`）对比 `:165-186`（`run_training` 用 `output_dir = os.environ.get("MA_OUTPUT_DIR", "/cache/output")`）。
- **证据**：
  - `run_training` 把 `--output-dir` 指到 `MA_OUTPUT_DIR`（默认 `/cache/output`），但 `sync_output_to_obs` 固定从硬编码 `/cache/output` 拷到 `MA_OUTPUT_DIR`。
  - 若 `MA_OUTPUT_DIR` 被设为 OBS 远端路径，训练产物写到远端，而同步却从本机 `/cache/output`（空/陈旧）拷出 → 产物丢失/错位；若保持默认值，则 `copy_parallel("/cache/output", "/cache/output")` 是自拷贝（moxing 下行为未定义/可能报错）。
- **修法**：让 `sync_output_to_obs` 与 `run_training` 共用同一环境变量解析出的本地暂存目录，再拷向 `MA_OUTPUT_DIR`。（DEPRECATED、仅云端环境，按 🟡 处理。）

## 阳性结论

1. **防泄漏红线全部兑现（活跃脚本）**：对比预训练数据集 `ECGContrastiveDataset` 默认 `split="train"`，且缺 manifest 时显式抛错、拒绝无划分全盘扫描（`dataset.py:227-247`），`train_backbone.py`/`train_simclr.py` 的预训练只读 train。CLIP 训练对只取 train（`train_ecg_text_clip.py:130` 的 `build_pairs("train")` 进训练循环，val/test 仅检索评估、不反传）；`build_pairs` 对 `report_splits` 与 manifest 划分不一致的记录**跳过并计数**（`:119-123`），双保险真正生效。`train_multimodal_fair.py` 全变体推理无任何文本输入（signal-only）。
2. **阈值来源全部正确（活跃脚本）**：`train_ecgfounder_head.py:244`、`train_multimodal_fair.py:137` 均用验证集 `youden_thresholds`；`train_backbone.py:198-199`、`train_ecgfounder_ft.py:142-143`、`train_simclr.py:184-185` 均用 `trainer.val_thresholds`（`trainer.py` 在 fit 内部于验证集现算并随 best 权重快照，`:370/:388-390/:407-409`）。无任何活跃脚本在测试集现算阈值。
3. **best_state/早停边界健全**：`trainer.train_multilabel` 用 `val_auc > best + 1e-4` 判定、`patience>0` 才早停（`trainer.py:380-402`）、训练结束回填 best 权重与对应阈值快照；`train_ecgfounder_head.py:182-198`、`train_multimodal_fair.py:116-127`、`train_ecg_text_clip.py:170-177` 三者均有 `best_state` 克隆 + `None` 兜底，不会 `load_state_dict(None)` 崩溃。
